## 1. 直接结论

**可以通过现有 Edge 候选找到所需的另一半证据，而且不止一条路径；当前自动选择规则仍未把它选进最终结果。**

当前要验证的功能是：初始直接检索得到证据集合 S₀，但尚不足以回答问题时，能否从 S₀ 中的节点沿合法 Edge 找到缺失的证据，并补全回答。直接检索提供起点；Edge 扩展负责补漏。本轮不以优于另一种直接检索或子问题检索方法为验收条件，也不要求目标节点重新取得很高的整题相似度。

最清楚的路径是：

> 已在 Top-10 中的 NGC 3256 摘要（明确写出约 1000 km/s） → BM25 候选边 → SN H0pe 摘要（明确写出最佳估计中心值 75.7 km/s/Mpc）。

这条目标摘要位于原 Dense 排名第 **26** 的页。此前讨论的指定 Gold 页位于第 **40** 名，也能通过另一条已有候选边到达。

本例首先值得做的是一个受控的选择实验：给模型已有证据，确认 H₂ 数值已经取得，让它从全部合法候选中选择补充 H₀ 的内容。不是先扩大 Stage 1、增加 hop 或训练 clustering。它是否能自动完成，仍需实际运行预先固定的选择规则；本文的事后查阅不能代替该实验。

## 6. “新的方法能不能做到”的准确回答

分四层回答：

1. **有合法候选路径吗？有。** 已通过完整 seed trace、原始 union 和五路候选 provenance 交叉核查。
2. **路径能带到真实答案证据吗？有。** SN p2 的文字、p11 的表格都直接给出所需中心值；p13 原图也含数值，但当前描述较粗。
3. **已有 P1 会自动选中吗？不会。** 四个图 arm 都未选 SN 页，实际动作仍集中在 NGC 文档。
4. **新讨论的需求状态/attention selector 已经证明能选中吗？尚未。** 本次没有运行该新 scorer，更没有用本题调参后的结果宣称方法成立。

现阶段可确认的是**召回机会与可读证据都存在**。下一步应让一个预先固定、只读取 query/已有证据/候选内容的选择器实际做决定，测它是否能自动识别缺口。

## 7. 下一步先验证：直接检索遗漏后，能否沿 Edge 补回

### 7.1 目标与动作

建议优先执行一个单题开发探针：保留初始证据，从合法邻居中选择能补充尚缺需求的节点，再检查能否完整回答问题。暂不训练大模型或扩大候选图。

流程：

> 原 query → 初始 Dense Top-10（S₀） → 根据 query 与 S₀ 识别未回答的要求 → 沿实际 seed 的 Edge 访问候选 → 选择补充证据或 STOP → 用 S₀ 加新增证据回答。

本题的示例状态是“H₂ 的最大本征外流速度已有支持；SN H0pe 的最佳 H₀ 中心值尚缺”。这必须由选择器读取 query 与 S₀ 后得到。本文已经看过 Gold，因此人工写出的示例状态只能用于说明或单独标记的诊断，不能当作系统自动识别成功的结果。

Edge 决策的目标是“这个邻居是否能补上当前还没有的证据”，而不是“这个邻居是否比 Dense 第 11 页更像整条 query”。目标节点的原始整题相似度低，不构成拒绝理由。相似度可作为特征，但不能成为再次过滤全部低相似度候选的硬门槛。

### 7.2 固定的最小协议

1. **固定起点与候选。** 保留原 Top-10 和 10 个实际 seed。第一轮沿用 P1 的全部 165 个图页面候选及其冻结代表 route，保持候选定义一致；不能人工只留下正确 SN 页。该集合沿用 P1 排除 Dense 第 11 页的规则，是为了复用本次诊断产物，不是未来 Edge 系统必须采用的限制。SN p2 的清楚文字证据已经在这些代表中，因此足以先检验选择机制。
2. **固定扩展预算。** 原 Top-10 不被替换，最多新增 1 页。动作是沿一条合法 route 选择目标页，或者 STOP。Dense 第 11 页及 P1 动作保留为历史参考，不作为此次新增页必须超过的相似度门槛。所有候选遵守同样的读取与评分预算；记录实际候选数、读取量和模型调用开销。
3. **只改变选择依据。** 同一固定 reader/评分器、同一候选集和动作空间下，比较“原 query”与“原 query＋已有证据＋尚缺需求”两种输入。预先固定提示及输出格式，要求记录 source、target、所补需求及引用片段。状态生成阶段只读 query 与 S₀，不读候选答案、Gold 或后验选中的页；候选评估阶段才读取相应候选内容。
4. **不混入标签。** 选择器不能获得 Golden answer、Gold 页、Gold node ID、预填的缺失答案数值或“必须选择 SN p13”等提示。已在 S₀ 中读到的数值可以作为已有支持；禁止的是预先填入尚未检索到的答案。
5. **冻结动作后验收。** 用同一个 reader 分别读取 S₀、S₀ 加新增页。检查新增内容是否真实支持缺失 H₀，回答是否同时覆盖两项数值与正确单位，并保留引用。表格/图片需要可靠读取，不能只给事后已知的正确候选额外内容。

这与 P1 的“和 Dense 第 11 页竞争”是不同的决策协议。两种新输入应在上述相同动作空间内比较；不能将新结果与 P1 的差异全部归因于需求状态，因为 Dense 竞争门槛也已改变。

### 7.3 按失败位置验收

| 要检查的环节 | 本题已知状态 | 下一步记录 |
|---|---|---|
| 初始检索是否遗漏必要证据 | Top-10 全是 NGC 文档，没有 H₀ 支持 | 系统能否仅根据 query 与 S₀ 识别该缺口 |
| 已有 seed 是否通过合法边连到补充证据 | 已确认可达，SN p2 有清楚文字，p13 有原图 | 固定候选与来源，避免事后补边 |
| 选择器是否沿边选中有效证据 | P1 没有选中；新选择器尚未运行 | 是否选出能支持 H₀ 的目标，引用是否正确 |
| 新证据是否使答案补全 | 人工核查显示存在充分内容 | 同一 reader 的扩展前后答案与证据支持 |

原 Gold-page 命中作为独立指标继续记录，但本轮的功能性成功是“此前缺失的必要信息得到有来源的支持”。例如选中 SN p2 的正确摘要，可以判为补回 H₀；仍应如实记录未命中原来指定的 SN p13，不能改写冻结 Gold。

本题已经被详细查看，只能作为开发/机制样例。若单题流程跑通，再在预先划定的问题集上报告：初始证据不完整的题数、其中缺失证据可达的题数、可达后被选中的题数，以及最终完成回答的题数。每项给出分母，同时单列“没有可达候选”“有候选但未选中”“已选中但读错”。离线可用标签确定初始遗漏组；在线决策仍只能根据 query 和当前证据判断。还应在初始已完整的题上记录无必要扩展与答错情况，检查 STOP 行为。

### 7.4 本轮不设检索方法胜负门槛

当前验收不要求 Edge 优于重新执行 Dense、BM25 或子问题检索。先把“直接检索漏掉 → 沿边补回 → 用证据回答”的流程做通。以后若要回答方法效率或比较优势，可以另设相同预算的检索对照，不把它作为本轮工作的先决条件。

已有 [旧 D1 记录](../EvidenceNet/output/budget_matched_dense_control_v1_20261106/budget_matched_diagnostics.jsonl) 第 7 行在该题仍只新增 NGC 节点，没有覆盖 H₀。它仅保留为历史背景，不承担本轮成功与否的判定。

### 7.5 找到之后如何保护证据

用户进一步明确了两个问题：如何识别有用的低相似度邻居，以及识别后如何保留。本节讨论后者，第 7.6 节补充识别标准。这里提出的是待实现、待验证的规则；没有运行新的证据核验或保留模块。

**保护单位是当前 query 下、支持具体问题要求的可核验内容。** 页面 ID、edge ID、attention 权重或模型生成的摘要，都不能单独代替证据。保护也不表示永久提高全局 edge 权重，或要求回答无条件接受该节点的结论。

#### 7.5.1 先判断是否提供支持，再进入保留集合

沿边发现的 target 先是候选。选择器需要读取其实际原文、表格或图像，记录以下信息，才能将它标记为当前需求的支持：

| 记录项 | 用途 |
|---|---|
| 对应的问题要求 | 明确它补的是哪一项信息，避免只看整题主题相似 |
| 原始 doc/page/node ID、段落或图表位置 | 允许回读，防止来源映射或摘要漂移 |
| 实际引用片段及必要上下文 | 保存实体、数值、单位、条件、表头或方法说明 |
| source→target 与候选来源 | 说明如何找到它；路径存在本身不证明内容正确 |
| 核验状态与理由 | 区分待核验、已有支持、存在冲突、已撤销；便于审查 |

核验应检查该内容是否支持准确的问题要求。例如 H₀ 问的是 SN H0pe 的最佳估计，不能只因为出现一个 H₀ 数值就通过；还需要保留“best estimate”等必要限定及其上下文。该过程读取 query、已有证据和候选原文，不能使用 Golden answer 或预填正确数值。模型给出的核验判断仍可能错误；开发阶段应事后审查，不将其自我确认当作正确性的证明。

#### 7.5.2 让保留规则贯穿排序、裁剪和回答

- **初始结果层：** 本轮仍保留 Dense Top-10，新增最多 1 页，避免新增页挤掉初始页面。这是实验中的保留约束，不代表 Top-10 的每条内容都正确，也不能保证加入新信息后答案质量必然不下降。
- **候选排序层：** 一旦目标被标记为某项需求的有效支持，后续排序不能仅因原 query 相似度低而删除该项唯一支持。重复提供 H₂ 信息的页面不能靠更高相似度挤掉唯一的 H₀ 支持。
- **上下文层：** 预留通过核验的关键片段及必要上下文所需的空间。检查最终实际送入 reader 的内容，而非只检查保留的页列表。压缩时不能删掉“最佳估计”、数值单位、图例、表头等影响结论的限定信息；只有来源 ID 而没有可读内容不算保留成功。
- **回答层：** 按问题要求逐项给出有来源的回答，再完成比较或综合。生成后核查引用是否支持对应结论；若仍缺一项，记录未完成或继续探索，不用无来源的补写掩盖缺口。

本题的示例是：保留 NGC 摘要中支持最大本征外流速度的片段；若系统实际沿边选中并核验 SN 摘要，则一并保留其最佳 H₀ 估计片段。本文已经人工读过两处数值，示例不等于系统已经自动完成核验与保护。

#### 7.5.3 预算满时按需求覆盖决定替换

本轮的 Top-10 加最多 1 页及读取规则，应在运行前固定并确保能进入 reader 的上下文。不能选中正确页后，临时给它更大读取预算；也不能名义上保留全部页面，实际截掉其中的关键支持而不记录。

未来允许更多 hop 或更紧预算时，可采用以下保留规则：同一要求有多份重复支持，优先保留来源可核验、条件完整且占用较少的证据；删除或替换前检查是否使某项必要要求失去支持。某个结论依赖多个片段或一段推导链时，应保留足以支撑该结论的整组内容，不能机械地规定“每个子问题只留一个节点”。

若所需证据在既定预算内放不下，应记录预算不足，并按预先制定的压缩或停止规则处理。不能通过提高一个相似度分数保证所有必要证据都保留下来。

#### 7.5.4 保护可撤销，且只对当前 query 生效

发现原文不支持、来源映射错误、读取错误，或得到条件更完整的替代证据时，应撤销或替换原支持，并记录原因。若出现相互冲突的内容，应保留冲突标记与必要出处重新判断，不能因为先前已保护就隐藏后来的反证。

本轮不因某条 edge 成功带来答案，就改写其全局权重或把目标永久设为高优先级。复用图结构与保存本次 query 的证据状态是两个不同动作；本节只讨论后者。

在第 7.3 节的验收中，增加“已选中但在裁剪中丢失”这一失败类型。对每项已标记的支持，检查其原文及必要条件是否实际进入最终 reader 输入，引用是否正确，是否无故失去已有覆盖。这样才能分清找不到、选不中、没保住和读错四类问题。

### 7.6 低相似度邻居是不是目标：用什么标准判断

当前整题 cosine 未能选中补充 H₀ 的内容，说明本例需要更明确的任务判断。目标应定义为“能支持尚未回答的要求，或提供有依据的后续探索线索”，不能定义为某个预先知道的 Gold node ID。下面是针对本项目提出的方案，并非已有实验结论。

#### 7.6.1 不知道答案数值，也能知道在找什么

从问题得到的是要求，不是答案。本题的两项要求可写为：

| 要求 | 对象与属性 | 必须核对的条件 | 当前证据状态 |
|---|---|---|---|
| r₁ | NGC 3256，warm H₂，流出速度 | 最大、本征速度、单位；不能误取投影速度或其他气体的速度 | 已有摘要提供支持，仍需系统读取并记录 |
| r₂ | SN H0pe，H₀ 测量的中心值 | 最佳估计及文中对应条件、单位；不能随意取一个早期或不同方法的结果 | 初始 Top-10 尚缺 |

r₂ 的待填内容可以是未知值 x。系统沿边读到候选后，先从原文提取 x 与其实体、测量条件、单位，再检查原文是否支持“SN H0pe 在所问条件下的最佳 H₀ 估计为 x”。不需要事先输入 75.7，也不能用 Gold 数值来查找匹配节点。

这些要求不应只靠精确关键词判断：文中可能使用同义表达、指代、公式或表格。允许利用可核验的上下文解析；若缺少表头、图例、方法说明，则标记待补充，不能自行补出条件。

#### 7.6.2 除相似度外，优先检查四件事

| 标准 | 要回答的问题 | 要求输出的依据 |
|---|---|---|
| 对象、属性与条件是否匹配 | 是同一个对象、同一个测量量、同一组必要条件吗？ | 对应原文或表头；不能只引用论文标题 |
| 是否有可读取的支持 | 能从候选或它与已有证据的组合中抽出所需内容吗？ | 数值/事实、单位、引用片段及来源位置 |
| 是否增加已有证据的覆盖 | 加入它后，哪个原先未回答的要求得到全部或部分支持？ | 扩展前后逐项状态；新主题本身不算有效增量 |
| 来源与结论是否相容 | 引用是否确实存在？条件、单位或已有证据是否有冲突？ | 原文核对结果；冲突时标记待判断，不能自动删除反证 |

这些检查针对“内容能否支持答案”。原文支持也不等于现实世界真值的绝对保证；在线判断可能出错，需要在开发数据上检查误判。多个模型都自信、多个节点重复相同文字，不能替代来源核验或算作多份独立证据。

本题的事后示例（数值不可预填到在线判别输入）：

- SN p2 摘要：给出最佳估计及对应数值，能够补 r₂。它即使原 query 相似度较低，也具备保留理由。
- NGC p15 的文献条目：虽然当前 q cosine 较高，本条内容并不提供 SN H0pe 的最佳 H₀，不能据此把 r₂ 标为已完成。
- SN p13 图：有多个方法/条件和多个数值，仅看到 75.7 或一个数值范围还不够；要读清对应图例，并确认其与问题中的“最佳估计”相符。必要支持不全时只能标记部分支持或待核验。

#### 7.6.3 用证据支持判断辅助阅读，不把它缩成新的任意加权相似度

最小可行判别器的输入是 query、已有证据 S、尚缺要求 r，以及合法 route 的 source 和 target 内容。输出应包括：它支持哪些要求、抽取内容、准确出处、尚缺的条件、可能冲突及建议动作。第一轮可用固定阅读模型进行结构化判别，配合原文定位、数值与单位核对；本文件不指定未经验证的模型或概率阈值。

可将其判断分成两个问题：

1. 从 S 与 target 中提取的候选结论 a，是否满足要求 r？
2. S 与 target 的实际内容是否支持该结论 a，而非模型仅凭记忆或猜测得到它？

文本部分可用蕴含判别或联合阅读评分辅助完成第二步；图片和表格需要相应的真实读取。这里的蕴含方向是“证据支持结论”，不是“问题与节点相似”。自动评分仍只是估计，不能当作正确性证明。将答案正确性与引文支持分开检查，可参考 [ALCE 的评价框架](https://aclanthology.org/2023.emnlp-main.398/)；该研究不直接验证本项目图文节点的核验能力。

若以后训练，优先考虑预测“在当前 query 与已有证据下，该 route 的 target 能新增什么支持/线索”的判别器。可用联合阅读结构学习这个任务；训练重点在监督目标，不在是否采用 Transformer。难负例应包含同文档但条件不符、相同属性但实体错误、只重复已有答案和引用不支持结论的候选。Gold 页面或答案字符串匹配不能自动替代这些细粒度标签，也不能把本题人工检查后的标签当独立测试集。

#### 7.6.4 不能把暂时没有答案的桥接节点全部删掉

| 内容状态 | 处理建议 | 能否计为完成缺失要求 |
|---|---|---|
| 直接提供有效支持 | 引用核验后进入当前 query 的证据集合，按第 7.5 节保留 | 可以，取决于条件是否完整 |
| 与已有片段组合才成立，或还缺条件 | 保留必要片段组合与待查内容 | 仅在组合支持充分后才可以 |
| 提供有依据的下一步指向 | 保留在待探索集合，记录它指向的实体、表格、章节或可访问邻居 | 不可以；它是线索 |
| 重复已有支持、尚无可识别帮助或存在冲突 | 分别记录重复、未知、冲突，按预算决定后续动作 | 不可仅凭高相似度计为新增支持 |

例如，一个节点写明结果见某张表，但本身没有数值，可以指引下一跳。也可能需要多个节点组合才有用，单个节点的即时增量为零，不等于整条路径无价值。可预留有限探索预算处理这类不确定候选；探索上限和规则应提前固定，不能看到 Gold 后无限扩展。

这些状态可以共存：同一节点可能既支持一项要求，又为另一项提供线索。不存在可识别指向时，也不能宣称节点必然无用；应记录不确定性。本轮先完成已有一跳直接证据的识别，若只找到线索且预算不允许下一跳，应如实报告未补全。

依赖已检索内容来选择后续路径，有 [Asai 等人的图检索工作](https://iclr.cc/virtual_2020/poster_SJgVHkrYDH.html) 可供参考。其图结构、训练数据与本项目不同；这里借鉴状态条件化的思路，不据此宣称本方法已有效。

#### 7.6.5 与保护衔接的下一步验收

下一次单题探针保留第 7.2 节固定候选和预算，先要求选择器输出每个候选对应的需求、支持片段、条件与证据状态，再做选择。初次诊断不要在这个判断前，按原 query cosine 再丢掉低相似度候选；完整阅读与核验的开销需计入记录。

动作冻结后检查：

- SN p2 是否凭实际内容被识别为 r₂ 的支持，且没有预填答案或指定页提示；
- NGC 高分文献条目、重复 H₂ 内容是否被误判为补全 H₀；
- 图中“有数值但条件未核实”是否与充分支持区分开；
- 真正选中的支持片段及必要上下文是否进入最终 reader，是否被正确引用。

可暂存后验人工审核结果，用于定位判别器的漏选和误选，但本题已被反复检查，不能作为独立盲测。完成开发后，再冻结规则在未用于设计的问题上检验识别与保留是否可靠。用户当前要求是方案说明，本次不运行该判别器。

## 8. 此题的标签与评价注意事项

- 原始 Golden answer 把 H₀ 称为 cosmological constant，术语不准确：这里是哈勃常数。速度的 km/s 与 H₀ 的 km/s/Mpc 量纲不同，不能据此宣称一个物理量“比另一个高若干倍”；可给出两项数值并说明它们衡量不同量。
- 指定 H₂ Gold 为 NGC p6 的文本，但冻结 p6 原文/图中未定位到 1000 这个最大本征速度；该数值清楚出现在已经取得的 p2/p13。需要复核 Gold element/页定位，不能把当前 Gold bbox 当作已确认的数字出处。
- SN p2 的 OCR 不确定度与 p13 原图等位置存在差别；本题只问中心值，多个位置一致为 75.7。后续若训练误差范围，应回读原图核验，不能顺带将 OCR 的误差条当真值。
- 原问题本身已给出两个研究名称，因此可从问题及初始证据识别缺失需求；这不会使本例失去“直接检索漏掉后，沿边补回”的诊断价值。

这些问题不妨碍用本题调试“候选已找到却未被选用”的机制，但不宜不经审核就把它作为干净的关系/答案监督。本文不修改冻结 Gold。
