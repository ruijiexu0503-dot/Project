## 2. 研究目的

研究目标是：直接检索遗漏必要信息时，从已有节点沿 edge 找回缺失证据，使最终 VQA 回答更完整、更正确，并能定位到支持结论的原始区域。

准备的数据应支持分别评价：

1. 必要证据是否在文档池和图候选中存在、是否可达。
2. 系统是否选中并实际读取该证据。
3. 证据集合是否足以回答问题的全部要求（answerability）。
4. 回答中的具体结论是否被原文、表格或图像支持（evidentiality）。
5. 最终回答是否正确完整、引用位置是否可靠。

多文档、多证据、并行比较与依赖前一步的 multi-hop 应区分。不能要求所有问题都有一条唯一有序路径，也不能把“访问更多 node”当最终目标。

## 5. P1：在独立目录整理可用文档池

推荐输出根目录为 `DynamicEdgeGraph/datasets/node_vqa_reuse_v1_<实际日期>/`，确认不覆盖已有目录后再创建。版本和日期按实际执行时记录，不沿用旧任务书日期伪装新运行。

优先引用已有不可变资产，必要时复制到新目录；保留 canonical IDs，不用文件顺序重新编号。至少维护以下清单：

| 清单 | 必须保留的信息 |
|---|---|
| `documents.jsonl` | 原 doc ID、数据集版本、标题、原始/本地来源、格式、SHA-256、页数、文档家族与资源状态 |
| `pages.jsonl` | 原 doc/page ID、物理页序与显示页码、原图/渲染文件、宽高、旋转、坐标约定、来源 |
| `nodes.jsonl` | canonical node ID、doc/page、类型、bbox、完整 content、单独 context、OCR/表格/视觉描述字段、原文件路径 |
| `asset_manifest.json` | 输入与输出指纹、生成工具/现有脚本版本、参数、时间、失败项 |
| `issues.jsonl` | 缺文件、解析失败、坐标不明、重复、内容不全、标注冲突及受影响对象 |

PDF 校验应确认文件确为 PDF、可打开、页数可读取，并记录文本/图像可用性。不是所有文档都必须已有可选中文本层；扫描件可以保留，但标记其 OCR 需求。

若只有 HTML 或旧渲染页，保留真实来源。不要为了满足“PDF”这个名称把衍生打印版冒充原始 PDF；若以后确需转换，另存衍生资产并记录坐标变化。已有页面图像和来源映射能支持部分 VQA 工作，不应因为缺 PDF 名称就全部弃用。

不要只保留 Gold 页或 Gold node。完整文档、非 Gold 内容与合理干扰项也是检索实验的一部分。

## 6. P2：保留完整内容，并拆开 node 的两层

已知旧节点输入包含：

- `context_text`：文章标题与页面 headings。
- `content_text`：节点自身的文本、表格、caption 或图像描述。

现有表示是联合编码 `Enc(context + content)`，不是两个可直接按向量维度切开的层。本阶段整理文本和来源，不生成新 embedding。

这两层应独立保存，完整原文不因检索预算而被覆盖。另设 `preview` 或运行时窗口字段，记录实际可见范围；禁止把预览文本保存为唯一内容。

此前已有一个实际失败：SN H0pe 摘要完整检索视图有 1,774 字符，包含最佳估计数值，但 reader 只看到带 context 的前 500 字符，答案被截掉。因此本阶段必须检查“源内容存在”与“模型输入包含它”之间的区别。

图像描述不能替代原图，表格序列化不能丢掉表头、单位和单元格关联。每个必要视觉证据应能回到页面及对应区域；不明确的映射进入 issues，不猜 bbox 或 node ID。

## 7. P3：复用现有 QA 与证据，不把自动生成内容直接称为 Gold

优先读取原有问题/答案/证据的 schema、manifest 与数量，保留原版本和来源。对已有明确划分的测试集，完成结构完整性检查即可；不要用其具体答案反复设计检索规则或生成提示。

建议整理：

- `questions.jsonl`：原问题 ID、文本、语言、任务类型、来源、拆分、关联文档范围。
- `answers.jsonl`：参考答案、允许的等价表达、已有数值/单位约定、原标注来源与审核状态。
- `evidence.jsonl`：问题 ID、doc/page/node 或 region 映射、原文/视觉位置、支持哪项要求、是否必要及其标注依据。
- `question_requirements.jsonl`：问题要求及依赖、已有证据覆盖、尚缺条件；自动抽取内容标为 provisional。

必要性、可回答性和关系类型不能从“它是 Gold 页”直接推断。若旧标注仅到页面级，不把该页全部 node 标成正例；若没有明确必要性标签，保存 unknown，不能自动填 necessary。

存在替代正确证据时，可在独立审核的扩展层记录，不覆盖原 benchmark Gold。旧 Gold 可能有术语、单位、页码或 OCR 问题；将问题列入 sidecar 审核记录，保留原标注可复现。

若旧数据没有 QA/答案或证据位置，第一阶段交付完整文档与节点池，并明确未完成项。可以整理待审核问题草案和候选证据，但不得把它们报告成正式 Gold 数据或模型效果。新问题设计应让答案需要实际内容，避免仅靠标题、常识或一个重复片段完成。

## 8. P4：面向多证据与 VQA 的数据质量审查

建议在开发数据中检查以下类型是否存在，而非强制所有题都标成 multi-hop：

| 类型 | 检查内容 |
|---|---|
| 单项抽取 | 原文或图表中能找到实体、数值、单位与条件 |
| 并行多证据 | 各子问题分别有支持，单一片段不足以覆盖全部要求 |
| 比较/计算 | 比较对象、量纲、时间与条件可对应；推导能回指输入证据 |
| 依赖型多跳 | 前一步给出下一步所需实体、限定或定位信息，有真实依赖 |
| 部分支持/不可回答 | 在明确文档范围内缺少必要信息；经过审核，不能只因检索未找到就判为不可回答 |

同一题可以有多个充分证据组合。Gold 集合不是唯一有序路径，未标注候选也不自动是负例。

数据阶段预留 answerability 与 evidentiality 字段，但只填写有依据的状态：前者针对整组证据能否完成问题，后者针对具体结论与原文/图表支持。引用字符串出现、JSON 解析成功或命中正确页面，都不能独立代表支持成立。

## 9. 拆分与冻结

尊重已有合理拆分；若旧拆分共享文档，需要先报告并建立独立的新划分版本，不静默移动旧测试题。

新划分优先按文档家族、同一论文的不同版本、近重复内容及共享文档关系组织。同一问题关联的多个文档不应被随意拆到训练与测试两侧。共享节点和正反 pair 也不能当独立样本随机拆分。

若采用开发诊断子集，记录选择规则与范围。不要先看哪些题能让 edge 获益，再把它们选成测试集。数据暂时不足以可靠拆分时，明确只作为开发集，保留后续独立评测需求。

输出 `split_manifest.json`、`SPLIT_AUDIT.md`；清楚记录复用旧划分还是新建划分、重复检查方法及未解决风险。

- `README.md`：用途、数据版本、规模、目录与读取方式。
