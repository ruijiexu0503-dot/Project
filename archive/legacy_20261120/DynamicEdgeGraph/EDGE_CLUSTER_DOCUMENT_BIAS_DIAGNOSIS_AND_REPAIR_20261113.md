# Edge 聚类为何按文章分组，以及如何转向关系表示

日期：2026-11-13。状态：已完成只读复核，新增本文；没有修改代码、冻结向量、候选池、聚类标签或旧实验输出，没有重聚类或训练。

## 1. 结论

**用户指出的文档集中现象确实存在。当前 E0 聚类没有学习“跨文章的相似关系”这一目标，因此不能把这些簇当成已经发现的关系类型。** 应先改变关系表示与验证方式，再决定聚类参数。

同时需要收窄“每个 cluster 都是同一篇文章”的判断：当前 Mid 中有 16/32 个簇、MidDiff 中有 10/32 个簇，至少 80% 的簇内去重节点来自同一文档。部分簇混合了很多文档；这也不能证明它们已经按关系分组。

建议下一步先建立“同关系、不同文章”和“同文章/主题、不同关系”的独立审核样例。在同一批候选上验证关系表示能否区分两者。暂不通过提高 K、强制混合文档或增加 prototype attention 宣称修复成功。

本文讨论的是沿 edge 补回缺失证据所需的表征改进，不将战胜直接检索作为当前验收前提。

### 3.3 现有指标的问题

[cluster_edges.py](stage2_edge_construction/src/cluster_edges.py) 第 52–59 行的 `document_entropy_bits` 只对 `same_document / cross_document` 二分类算熵，未统计实际文档 ID。因此它不能诊断“簇是否等于某篇文章”。

[audit_edge_clusters.py](stage2_edge_construction/src/audit_edge_clusters.py) 比较簇内两端的 node cosine，仍使用构造 edge 的同一个节点空间。高 node cosine 可来自聚类目标本身，不是独立的关系质量证明。其所谓 PCA 是未中心化的 SVD 可视化，未参与 K-means；不能将文档集中归因于该二维投影。

## 5. 原因：输入几何没有把关系作为首要区分维度

### 5.1 已确认：表示是端点组合，没有关系学习目标

[representations.py](stage2_edge_construction/src/representations.py) 第 12–20 行：

\[
m_{ij}=\tfrac12(h_i+h_j),\qquad d_{ij}=h_j-h_i,\qquad e_{ij}=[m_{ij};d_{ij}].
\]

MidDiff 可逆回两个端点。输入中的主题、实体、文章上下文因而会保留；这个代数操作没有教模型哪些变化属于“关系相同”。

对未归一化的 MidDiff，两个 pair 的内积可展开为：

\[
e_{ij}^{\top}e_{uv}=\tfrac54(h_i^{\top}h_u+h_j^{\top}h_v)-\tfrac34(h_i^{\top}h_v+h_j^{\top}h_u).
\]

这说明其几何由端点相似性组合而来。逐 pair 归一化会改变尺度，不会自动新增“测量结果→不确定度”等关系监督。该推导不证明所有关系信息都不存在，只说明关系抽象并未因拼接自动完成。

K-means 随后仅寻找这个空间里的相近向量。标题、主题或内容格式若是强信号，它按这些信号分组符合当前优化目标。代码没有将 document ID 当作数值特征直接输入，因此这里是表示包含文章相关信息，不是发现了把 ID 喂给模型的实现错误。

### 5.2 已确认：原始候选和节点输入提供了强文章信号

- [Top-100 sensitivity](stage1_candidate_pruning/outputs/vldocir-pilot-stage1-v1/candidates_top100/analysis/topk_sensitivity.csv) 中，union 的跨文档 pair 为 263,232/950,871；即同文档约 **72.32%**。
- 5,000 对聚类样本中同文档为 **3,631/5,000 = 72.62%**，基本继承原分布。仅 343 对是同页，问题不等于“只连接相邻页面”。
- 7,288 个检索视图均带页面 context，含文章标题和部分标题层级；节点正文很短时，标题是明显的输入内容。共享标题影响到底有多大，仍需固定 pair 的受控消融才能判断。
- 均匀抽 pair 不等于均匀抽文章或节点；重复端点和反向边也不是独立观察。不过在 5,000 个无向 pair 中，最大单节点端点出现次数为 9；双向展开后的 10,000 条 edge 中对应为 18。本次不能声称少数 hub 已垄断聚类。

### 5.3 实际编码与旧说明不一致，需要按真实产物设计消融

[Input manifest](stage2_edge_construction/outputs/pilot_e0_stage1_v1/input_manifest.json) 指向 Stage 1 的 Qwen3 `view_vectors.npy`。对应 [embedding_summary.json](stage1_candidate_pruning/outputs/vldocir-pilot-stage1-v1/models/qwen3_0_6b_dense/embedding_summary.json) 明确记录 `max_length=512`、`pooling=last_token`。

[vldocir_freeze_embeddings.py](stage1_candidate_pruning/src/vldocir_freeze_embeddings.py) 第 54–59 行对完整检索文本进行截断并池化。它不是 [node_representations.py](stage2_edge_construction/src/node_representations.py) 第 98 行报告文本所述的“context 限 64 tokens、正文按窗口完整覆盖后均值池化”。

这意味着共享 context 与正文截断值得单独检查；本次没有统计每个节点丢失了哪些 token，也没有运行去标题实验，不能将全部文档集中归因于截断。

### 5.4 Diff 与加权不能替代关系抽象

若用简化模型把端点写成“文章成分＋节点内容”，同文档 diff 可能抵消共享文章成分；跨文档 diff 又包含两篇文章的差异。真实编码还存在上下文非线性，不能假设相减一定去掉标题。

MidDiff 仍保留 midpoint，而且相似端点的 midpoint 能量可能更大。独立块归一化、减去文档均值、去掉前几个主成分都只能作为诊断；它们也可能删掉实体、条件或类型等真正需要的信息。仅将 mid 换成 sum，在行 L2 后甚至不会改变方向。

## 6. 修正路线：保留内容身份，单独学习或抽取关系模式

### 6.1 先定义本项目要找的关系，允许多种用途与未知

一条关系实例至少包含：两端分别扮演什么角色、通过什么具体联系相连、成立的条件、两端原文依据。可从以下可审核模式开始，而非宣称必须采用固定标签体系：

| 模式例子 | 需要的依据 |
|---|---|
| 测量结果 → 该测量的不确定度/适用条件 | 同一对象、测量、方法/条件匹配，有原文连接 |
| 变量定义 → 同一变量的使用 | 符号或指代可解析，不能只因同名 |
| 文字结论 → 支撑该结论的表格行/图中结果 | 数据与结论条件对应，不能只因 table→text |
| 两个对象的同一指标在匹配条件下比较 | 指标、单位及必要条件可对齐 |
| 文内引用 → 被引用的证据或方法 | 指向可核查；引用本身不代表结论为真 |

同一 pair 可以有多个模式，也可能缺乏足够上下文。未发现稳定静态关系，不等于它对所有未来 query 都无用。

H₂/H₀ 案例中，两处证据因本次问题要求联合回答而互补。两种量的单位和物理含义不同，不能在离线时强行标为“同一物理指标比较”。这类互补用途需要保留到 query 与已有证据状态下判断。

### 6.2 为关系聚类增加独立输入，不改冻结检索表示

建议保留原有节点内容、来源和检索向量；另建小规模关系表示探针：

1. 联合读取两端必要内容及有依据的局部上下文，产出两端角色、连接方式、成立条件、支持片段和不确定状态。
2. 关系聚类视图中弱化反复出现的文章标题、URL 碎片和专名指纹；可对实体名称做保留角色的一致替换。原始内容保留，供实体绑定、事实核验与在线检索使用。
3. 必须保留影响关系的实体类型、否定、单位、时间和条件；不同对象不能都替换成同一个占位符。同一对象在两端出现时也要保留同一性。
4. 比较“原 E0”“正文为主的 E0 控制”“结构化关系描述/联合 pair 编码”。冻结 pair 集、预先固定描述规则、读取预算和编码器；描述不能根据已知 cluster ID 或 Gold answer 编造联系。

这是拟议探针，尚未执行。用模型生成描述不等于获得真关系标签；只有描述能回指原文且通过独立审核，才适合进一步使用。也不能将自己生成的关系类别直接编码成向量，然后用同一类别计算聚类纯度，形成循环评价。

低信息的页码和页面操作节点，可先在关系原型拟合视图中标为不可判定或降低采样权重；保留原始图及节点引用。不在当前阶段直接删除所有这些候选，以免误删实际有用的短节点或改变补漏可达性。

### 6.3 若要训练，训练跨文章关系可迁移性

构造三元组：anchor 是一个 pair；positive 是不同文档/主题下、具有相同可审核关系模式的另一个 pair；negative 是同文档/相近主题下、关系不同的 pair。避免共享 node、近重复文本或仅靠相同表格模板即可认出的捷径。

训练/评价希望满足：

\[
\operatorname{sim}(r_a,r_{\text{同关系异主题}})>
\operatorname{sim}(r_a,r_{\text{同主题异关系}}).
\]

这里的 positive/negative 由原文关系判定，不由文档是否相同判定。**不能把所有跨文档 pair 当正例，也不能把所有同文档 pair 当负例。** 多关系重叠、方向对称和未知情况要保留，避免制造假负例。

关系学习文献中已有相近原则： [RelBERT](https://aclanthology.org/2021.emnlp-main.712/) 用关系相似性训练 word-pair 表示；[Learning from Context or Names?](https://aclanthology.org/2020.emnlp-main.298/) 使用实体遮蔽与关系对比学习来减少只记名字的倾向。这些结果支持设计思路，但它们的对象主要是词对/文本实体关系，不是本项目的多模态节点，不能直接保证迁移效果。

对本项目而言，训练目标首先是角色、连接和条件，模型是否采用 Transformer 是实现选择。仅把已知 Gold 页节点配成正例，无法保证得到上述关系监督。

### 6.4 直接把 node 的两层拆开检查：当前优先做的表示消融

这里的“两层”按实际字段解释：`context_text` 是文章标题与页面 headings；`content_text` 是节点自身的文本、表格、caption 或图像描述。后者仍保留原有模态字段，不等于只留纯文本而删除图像信息。

本次已逐条核对保存的 [node_representations.jsonl](stage2_edge_construction/outputs/pilot_node_representation_v1/node_representations.jsonl) 与 Stage 1 的实际检索视图：**7,288/7,288 条拼接文本完全一致**。因此两层原始文本可以直接按 node ID 分开读取，无需猜测拆分。

| 本次只读文本统计 | 数值 |
|---|---:|
| 不同 context 字符串 | 424 |
| 不同 content 字符串 | 7,075 |
| 不同 joint 字符串 | 7,219 |
| context 比 content 更长的节点 | 1,835/7,288 = 25.18% |
| context / content 字符长度中位数 | 130 / 313 |

长度按保存字符串的字符数计算，包含模态标签；它不是 token 数、attention 权重或因果贡献。正文只有 `A-5` 的节点，其 context 是文件名及 Eligibility / Administration 两个标题，这说明拆分对诊断有直接价值。

**当前向量不能直接按维度切成两半。** 真实计算是：

\[
h_i=\operatorname{Enc}(\text{context}_i\Vert\text{content}_i),
\]

而不是分别编码后拼成 `[h_context; h_content]`。当前是一个联合的 1024 维向量；拆文本后需要分别编码得到新派生表示，不能从旧向量中截取前后 512 维或减去 context embedding 来声称恢复 content embedding。本轮没有执行这些编码。

建议最小四组：

| 组别 | 输入与作用 |
|---|---|
| J：joint | 保存的原向量与原聚类，作为参照 |
| C：context-only | 仅标题与页面 headings，测仅凭 context 能形成怎样的文档集中 |
| T：content-only | 仅节点内容，保持相同 encoder、pooling 与最大长度 |
| T-match：匹配正文范围 | 只编码原 joint 截断后实际可见的正文范围，控制去 context 后正文读得更多的影响 |

固定 5,000 pairs、双向展开、edge 公式、K、seed、归一化及全部 node ID，不重建 Stage 1 图，不改冻结检索结果。正文范围需用真实 tokenizer 对照并记录，保持类型标记和原始内容顺序；不能把 T 比 J 好全部归因于去标题，因为原 joint 总长度 512 会让 context 占用正文空间。

context-only 中共享相同 context 的节点可能形成相同向量，导致很多零 diff。要记录重复 context、零 diff、空簇与有效簇数，不静默丢掉这些 pair 后再与原结果比较。C 主要用于诊断，并非建议把它当关系表示。

先观察文档集中度，再用独立关系样例检查跨文章同关系的可辨识性。若 T-match 改善，支持显式 context 对聚类有影响；若仅 T 改善，需检查正文覆盖范围；若内容层仍明显按文章分组，还需解决正文主题与关系表示的区分。任何文档混合度变化，都不能单独证明关系质量提升。

后续可让 content 侧承担具体内容/关系候选判断，让 context 作为实体定位、条件解析和消歧的辅助输入。必要的局部标题、表头和图例不能一律删除。仅在这轮拆分显示明确影响后，再区分“全文章标题”和“局部上下文”，避免一次扩大过多实验组合。

## 7. 先做什么：最小可复核方案

### 第一步：补齐可审查内容与关系对照

现有 [pair_review_sheet.csv](stage2_edge_construction/outputs/pilot_e0_stage1_v1/pair_review_sheet.csv) 有 160 行，但本次检查全部仍为 `UNREVIEWED`，而且 160 行 source/target preview 都为空。不能将这张表当成已具备原文的关系审核集。

先恢复可定位的原文、表格和图像读取入口。围绕本次强文档簇、混合簇及原 160 对，建立一小批关系对照：同关系异文章、同主题异关系、同文档同关系、异文档异关系都要包含。每种模式需跨多个文档/主题，否则无法区分关系与文章身份。

样本量先以能够完成独立审核为准，不为了凑数臆造正例。对每个判断保留角色、条件、引用及分歧；遮蔽已有 cluster、route 分数及模型预测。已被反复检查的 Pilot 作为开发集，不冒充未见测试集。

### 第二步：先测表示，再重聚类

先测上述三元组判断率和跨文档关系近邻质量，并报告关系/主题子组。内容长度、模态、端点相似度和 route support 作为干扰因素做匹配诊断；同时保留自然分布样本，不能只选原模型失败的例子。

| 方案 | 改动 | 回答的问题 |
|---|---|---|
| A：保存的 Mid / MidDiff | 无 | 当前关系与主题区分能力如何 |
| B：内容与 context 分离的控制表示 | 只改关系实验输入视图，保留必要条件 | 共享标题和无信息片段影响多大 |
| C：有原文依据的关系描述/联合编码 | 改关系表示，候选不变 | 显式角色与条件能否提升跨主题关系区分 |
| D：有独立监督的关系编码器 | 关系对比学习，数据划分冻结 | 关系结构能否迁移到未见文档 |

B 并非被预先认定一定更好；删 context 后若角色或实体解析变差，也应保留这一负结果。三元组与近邻检查不要求先决定 K，能避免为了簇形状反复调参。

### 第三步：通过关系检查后，再评估聚类

在训练文档拟合原型，在未见文档赋值。按文档族划分，反向 pair、共享端点与近重复不能随意跨集合；跨分区的 pair 需明确处理。可在开发集做有限 K/seed 敏感性分析，但不能在测试集选最好参数。

同时报告：独立关系质量、具体文档 ID 集中度、unique endpoint 与 occurrence 两种口径、完整模态方向、簇大小和稳定性。文档平衡抽样可作为控制，必须同时报告自然候选分布；仅让每簇文章数相等不算成功。

原型允许多种适用模式与未匹配状态。Soft assignment 能缓解单一 cluster ID 的限制，但不会自行创造关系语义。

### 第四步：回到沿 edge 补漏的原始目标

固定初始检索、合法邻居、读取预算和 reader，检查加入关系信息后是否更容易选出能补当前缺口的节点、是否错误挤掉已有支持。与同一流程不使用原型的版本对照，是为了定位聚类是否帮到了补漏，不要求它击败另一种检索方法。

原始 edge 与原文应保留。关系原型只提供模式信息，不能把另一个 cluster 成员的事实、答案数值或来源复制到当前 edge；也不宜未经召回审计就成为唯一不可绕过的候选门槛。

## 8. 不能单独当作修复成功的操作

- 调大/调小 K 或改用另一种聚类算法：改变分组方式，未指定希望学习的关系。
- 强制不同文章混合、删除所有同文档 edge：可能让图好看，却损失真实的文内支持与下一跳。
- 只用 diff、按文章减均值或删所有标题/实体：有诊断价值，但可能同时删掉成立条件，不能保证关系信息保留。
- 把更高 silhouette、更低 document purity、正反边更容易分簇当最终目标：这些都不是关系正确率。
- 给同一套主题原型增加 attention：若原型仍以文章为主，不能据此认为已变成关系上下文。

**本轮优先交付应是关系对照样例与表示诊断，而不是一份新的 K-means 图。** 只有先证明不同文章的同类连接能被识别，聚类才有可靠依据把它们组织为关系原型。
