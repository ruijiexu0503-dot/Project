# 必须加入 HF/ColNomic 对照：如何判断 EvidenceNet 是否更好

日期：2026-10-31。用户补充要求：除内部edge消融外，还要与Hugging Face相关工作的结果比较。

本文补充 [阅读顺序接入方案](READING_ORDER_EDGE_INTEGRATION_HANDOFF_20261031.md) 与 [改进计划](QUERY_SEMANTIC_EDGE_NEXT_STEPS_20261031.md)。这里规定待执行的对照，没有产生新的比较指标或提交任务。

## 1. 比较对象与结论范围

目前可直接复用的是：我们此前在**相同24个query、518页检索库**上运行HF发布的ColNomic-7B原图检索模型所得的完整页面分数。

它是本地同库复现，不是作者官方全集的逐题结果，也不是其Ctx/Rerank/Ensemble变体。官方总体结果可作另列参考，不能与518页pilot直接宣称胜负。

第一阶段完成同库公平比较；只有按官方完整语料、query、qrels及协议运行后，才能报告对应官方全集比较。当前24题反复调试，必须标为开发集；新冻结测试另存、另报。

## 2. 两个问题分开回答

### A. 找得更好吗？

比较页面级Recall@5/10、AP@5/10、nDCG及完整gold页召回情况，保留每题排名和变化。

- node结果先按预先固定规则映射为去重页面排名；Top10 node不等于Top10 page。
- 来源集合命中率不是AP；没有排序输出时不得用来源覆盖代替排名指标。
- qrels、页面ID、重复页处理、排序平局规则和AP分母采用同一评测器。
- 图方法得到的候选如果重排，内部所有检索arm使用相同后端重排器；同时保留原始ColNomic排名作为模型原生基线。

### B. 最后给LLM的证据更精准、更少吗？

比较相同最终token预算下的原文充分性、必要约束保留、遗漏和冗余，再比较同等充分性需要多少tokens。

**必须有 `ColNomic检索 + 相同原文选择器` 这一组。** 否则拿ColNomic整页与EvidenceNet精选段落比较，会把选择器带来的收益全部算到图上。

可以额外报告“ColNomic整页输入”作为常见使用方式，但不能把它作为唯一外部对照。

给ColNomic召回页使用相同的冻结解析原文及packet/span映射；不按gold框裁剪，不额外提供图方法看不到的证据。页候选与node候选粒度不同，必须报告实际暴露的页、node、原文量和模型成本，不假装相同TopK就等成本。

若比较实际图像输入与文本输入，分别报告视觉输入数量/处理成本和文本tokens，不将其简单等同为字符或文本token数量。当前不要求最终答案LLM，只评价证据选择。

## 3. 建议对照矩阵

| 组 | 检索/导航 | 文本证据处理 | 用途 |
|---|---|---|---|
| H0 | 原始ColNomic页面排序 | 不加选择器，仅报页级指标 | 外部模型原生表现 |
| H1 | ColNomic页面候选 | 相同原文选择器、相同最终预算 | 外部方法在同等定位能力下的表现 |
| N | 原node similarity，无edge | 相同选择器 | 内部无图基线 |
| R | 原node入口 + NEXT/PREVIOUS | 相同选择器 | 结构边增量 |
| S | 原node入口 + 语义边 | 相同选择器 | 语义边增量 |
| RS | 原node入口 + 结构边 + 语义边 | 相同选择器 | 完整图导航主组 |

H1与N/R/S/RS如使用额外页面reranker，应配置相同的reranker及预算，独立于H0列出。整query与子需求召回、encoder升级、压缩和扩大图需单独版本化，不能一组多用这些功能却全归因于edge。

比较两种资源口径：固定最终输入预算的质量比较，以及匹配在线总成本/暴露量的效率比较。报告真实花费，不强行宣称二者已完全匹配。

## 4. 必须展示逐题四类案例

1. ColNomic未命中，但图方法找到：给出原始排名、seed、实际路线、目标原文与最终保留片段。
2. ColNomic找到，图方法遗漏：定位召回、导航、选择或压缩哪一步丢失。
3. 双方都找到：比较支持是否同样充分，谁使用更少必要上下文。
4. 双方都未找到：分析语料/解析、图覆盖、排序或查询理解问题。

“找回”必须说明阈值：Top5外、Top10外、候选预算外，还是检索库中确实没有该内容。gold不完备时，替代来源需要原文审查，不能把所有非gold来源判错。

不得只挑图方法赢的题展示；保留完整分母、退化案例及尚未完成的题。

## 6. 当前不能声称的方法提升

最新语义edge v2每组只完成13/24题；两方法最终156个对应记录的选文一致。它没有形成完整新排名比较，也不能凭435/249等最终tokens宣称优于ColNomic。

已知四题的历史比较本身也有互有胜负：ColNomic在Federer Top10可覆盖两张gold页，而旧无edge节点方法有一张排第12；Ce4f旧无edge方法的gold页排名更靠前。这说明需要同协议逐题对照，不能预设图一定更好。

## 7. 交付与验收

- 输出共享eval manifest，固定query、语料、qrels、模型、排名映射、预算及各arm配置。
- 复算历史ColNomic指标并对齐旧metrics，确认评测器没有改变定义。
- 新结果包含逐题排名、页级指标、最终证据、充分性审查、tokens与在线成本。
- 区分“相对内部无edge提升”和“相对ColNomic提升”，两项都报告。
- 如果只在开发pilot上有提升，明确限定范围；不称超越官方全集。
- 方法优劣可以是权衡：召回更高、同等充分性下更省输入、或更贵但更完整。没有明显收益时如实报告，不强行合成一个有利总分。

> 下一模型应将H0/H1外部对照纳入阅读顺序与语义图实验，优先核验并复用已有ColNomic分数。先比较相同query与检索库上的页级检索，再用共享原文选择器和预算比较最终证据。必须显示全部逐题胜负与成本，保留失败分母。不能拿精选片段与整页的天然长度差，冒充edge带来的提升。
