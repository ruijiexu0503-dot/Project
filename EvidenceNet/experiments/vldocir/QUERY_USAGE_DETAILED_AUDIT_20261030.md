# Query 使用及完整 span 实验审计（2026-10-30）

本审计对应 Top10 5218190 与固定池 5218191+5218364；两组各24题完成。结果只代表现有24-query开发集及冻结语义图，不是官方全集评测，也不是当前完整生产pipeline的端到端测试。旧结果与部署保持不变。

## 当前 query 实际进入哪些环节

1. Top10初始召回复用完整query的冻结Qwen3-Embedding-0.6B window分数；每个实际EvidenceNode取窗口最高分。没有按子问题重新检索。这里的query检索encoder与离线node-edge encoder不同，不能误称全部使用最新embedding。
2. 所有Top10 seed沿187条既有语义边双向扩展全部一跳邻居；此步不依据query选择路径，不使用query-edge embedding相似度，也没有第二跳。NEXT/PREVIOUS尚未导入该冻结图，不能将此结果视作完整阅读顺序图实验。
3. 同一次Qwen3.5-35B-A3B调用看到query+候选原文，输出1–6 requirements、每packet的0–3分及支持requirement的span ID。prompt要求requirements仅来自query，但不是与候选隔离的独立规划阶段。
4. 另一调用看到query+requirements+两端原文，判断edge useful布尔值。输入只含端点ID，没有原始关系类型、描述或关系成立依据；没有动态传入当前已选证据、剩余缺口。
5. Q1/Q2按新增requirement个数、支持分、原始召回分贪心选择原文。任一packet标为covers某requirement，该要求就视为完整满足，后续同要求gain=0即跳过。预算不足会跳过完整块，不截断。
6. span ID只用于引用来源校验；最终输入仍是整packet。本轮不生成最终答案。报告的370tokens仅为最终证据文本，不包括上游评分/gate模型所有输入输出。

固定池与Top10是不同候选设置，不能把两组差异直接归为edge增益。固定池为历史同池packet union，Q0/Q1/Q2都已使用query评分；Q0不是原始dense检索基线。Top10各arm共用union候选的模型评估缓存，控制评分一致性，但候选共同呈现可能影响判断。

## 无edge增益的具体机制

固定池879个query-packet中88个score=1（背景/桥接）全部covers为空。Q2相对Q1唯一额外准入条件是score1、gain>0且通过useful edge连接已选packet。因此本次预测下Q2不可能新增选文。9/112个useful提案：4个两端score>=2（Q1本来即可选）、2个score0↔3、1个两端score1无covers、2个两端score0。边判断与片段评分存在不一致，而且没有桥接后继续搜索机制。

Top10四个arm（seed10、同数量dense扩展、全部一跳邻居、query筛边邻居）最终文本在24题×4预算96个组合上全部相同。只有7/24题获得12个新query–node候选，7个评分0、1个评分1、4个评分2，全部没有covers。部分目标确实偏题，例如Federer2004/2005问题得到Graf及Federer2006相关内容，开幕式问题得到吉祥物名称。

Top10最终packer对所有arm调用Q1且传edges=[]。query gate只控制新增候选集合，不把关系用于证据联合解释，不提供bridge入选或多跳能力。

## 真实覆盖错误：候选已包含证据，却过早停止

以下都不是仅凭gold页未命中推断的错误，已对照实际选中/未选原文。最终输入中不保留其他候选上下文。

- Federer两年共同大满贯（df2f051f…）：P035单赛季表被标成同时覆盖2004、2005及交集，表中只有赛果与←2004/2006→导航；明确2004的P020和明确2005的P025被排除。选中326tokens，三块一起762tokens，1024预算足够。
- A2063G变化（d36e190e…）：P030只有总体76.6%及显著上升，被标成覆盖2019具体率和2024Q1具体率；P013表格给出75.2%与81.4%，却未入选。两者936tokens，1024足够。
- Graf奖牌年份（8fcc70a5…）：P033只提Barcelona银牌、无显式年份，却标成完整覆盖奖牌列表和年份；P004金/铜牌及P005明确1988的原文未入选。三块695tokens，1024足够。

这说明来源可追溯与支持判断正确是两回事；二元覆盖会放大评分中的过度推断。可能存在同批候选上下文串用，但尚未单独做实验验证该原因。

## 优先修正方向

1. 区分missing/partial/sufficient，并把年份、实体、所求数值作为来源约束；“一段提到某要求”不能使整个要求完成。枚举型问题保留多条新增事实，而非一次命中就停止。
2. 独立冻结query requirements，逐来源评估支持，最后审查选出集合是否真正满足问题。跨packet的联合支持必须显式引用所有必要来源。
3. 分离导航与最终reader证据：bridge不一定直接回答问题，也不一定送入reader，但可以继续扩展下一跳。由缺失证据控制有限步数与候选预算；与同候选数/同成本dense基线对照。
4. 图覆盖与边质量单独评估。对当前12个新目标不应通过无条件加分强行入选；再测有来源依据的关系描述、经验证的NEXT/PREVIOUS等独立消融。
