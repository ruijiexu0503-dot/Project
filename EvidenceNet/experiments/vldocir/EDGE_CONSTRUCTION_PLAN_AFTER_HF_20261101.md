# 基于 HF 对照结果的建边调整计划

日期：2026-11-01。面向下一位实现者；本文规定下一阶段工作，不表示这些改动已经实现。

本次已读取用户指定的 REPORT.md、comparison.json、retrieval_metrics.json，并检查 eval_manifest、逐题排名和已有建图代码。已保存本地快照 `migration/hf_evidence_comparison_review_20261101/`，校验 tasks、rankings、paired_cases 与 manifest 的 SHA。没有修改生产pipeline或提交实验任务。

## 1. 我的判断

**应该调整建边目标：在保留可靠语义关系的基础上，让图能连接“同一证据对象的不同组成部分、不同条件和必要上下文”，而不只发现两段内容相似。**

目前不能仅凭这次HF结果断言“edge生成模型本身无效”：完整阅读顺序层尚未进入此前语义导航实验，图覆盖很低，唯一实际访问还出现入口/目标收益混淆；此外，本次H1存在每页只取一个node的定位限制。

但可以明确：现有187条宽泛语义边，加上当前导航与选择流程，尚未产生可证明的最终证据收益。继续只改一个关系prompt或增加同主题边，不足以解决问题。

建议下一阶段优先做：

1. 补全可追踪的阅读顺序、页/章节到node的结构导航；
2. 建立原文支持的图表/公式/说明归属，以及身份和参数上下文；
3. 离线召回“同一对象但信息互补”的候选，再核验关系及两端各自提供什么；
4. 在固定在线成本下证明这些边让目标证据可达且被选中；
5. 同时修复页内定位，避免误把定位器的损失归因于图。

关系可以继续开放自然语言表达，不需要把所有语义边重新塞进很细的固定taxonomy。

## 2. 这次实验实际说明什么

范围：24个query、518页开发pilot，不是官方全集。H0是冻结ColNomic原始页面排名，N是原node similarity按页面去重的排名，**N不是有edge方法**。

| 指标 | H0 ColNomic | N node similarity | N−H0 |
|---|---:|---:|---:|
| Recall@5 | 79.17% | 83.33% | +4.17个百分点 |
| Recall@10 | 91.67% | 89.58% | −2.08个百分点 |
| AP@5 | 65.83% | 63.82% | −2.01个百分点 |
| AP@10 | 69.45% | 65.39% | −4.06个百分点 |
| nDCG@5 | 71.28% | 72.14% | +0.86个百分点 |
| nDCG@10 | 76.62% | 74.55% | −2.06个百分点 |
| Top10 gold页齐全题数 | 21/24 | 19/24 | −2题 |

Top10逐题：双方齐全18题、双方不齐全2题、仅ColNomic齐全3题、仅node方法齐全1题。原node检索并非全面弱于ColNomic，但还没有整体优势；提高Top5召回与提高排名、补齐所有证据不是同一件事。

### 2.1 H1有一个必须保留在解释中的限制

eval_manifest中的H1不是“把Top10整页所有内容交给选择器”，而是：

```text
ColNomic Top10页面
  → 每页选一个冻结node similarity最高的node
  → 将该node的可用原文packet交给同一选择器
```

H1 24/24执行完成，但1024预算下只有7/24题被模型判为充分，平均303.38文本tokens，最终来源页的平均gold覆盖39.58%。这不等于ColNomic只找对7题：它的Top10已有21题gold页齐全。

从页面命中到最终充分之间存在明显缺口；原因可能是页内选错node、必要上下文未携带、非文本信息不可见、支持判定或选择遗漏，需要逐阶段核实，不能把所有损失算到某一项。

共同完成的13题，1024预算下H1为4题模型判充分、平均223.62 tokens；S为3题、平均277.38 tokens；两者最终来源页覆盖均30.77%。当前没有证据表明S更准或更省。充分性是模型估计，非独立金标答案准确率。

S没有完整页面排名，不能算出或编造有edge的AP。也不能把H0完整24题与S的13题子集直接作总体胜负比较。

### 2.2 仍然需要保留的前序事实

前序S快照13题中：8题缺证据但Top10没有任何语义关联边，3题初始充分，2题进入导航；semantic只接受1条，新增访问没有改变最终选文。187边覆盖321个端点；这张冻结子图未载入reading layer。

这说明瓶颈至少分为：**结构图未接入、语义候选覆盖不足、导航增量判断错误、证据定位/选择损失**。建边计划必须针对前两项，并让后两项具有独立可测的接口。

## 4. 建图原则：结构覆盖、关系精度、信息互补分开

### 4.1 结构层应覆盖，语义层不强迫出边

NEXT/PREVIOUS、文档/页包含关系可以提供稳定的导航骨架。对有效、多node文章，阅读链尾部必须可以反向访问；单节点、缺页和顺序未知需要明确例外。

语义层仍然是“每个合格node有候选召回机会，通过核验才建边”，不保证每node至少一条语义边。不做全量N²核验，也不把“平均度数提高”作为质量成功指标。

### 4.2 保留RELATED，但增加有来源的用途说明

宽泛RELATED可以继续作为兼容标签。新增字段应描述：共同对象、双方各自信息、不同条件、来源位置、适用范围及局限。它们帮助检索用途判断，不要求固定成几十种关系类型。

例如，离线可核验的陈述是“这段正文解释图6中参数条件与曲线变化”；不应生成“这条边能回答某测试题”这种query-dependent事实。

### 4.3 互补性是优先检验的假设，不是强制规则

相似边容易把已经相似、也已经被dense召回的内容重新连接。建议提高有明确原文依据的补充关系的候选占比：数据与解释、对象与定义、同对象不同年份/条件、模型与对应测量。

重复表述仍可用于消歧或佐证，不应一律删掉；但要标为重复/佐证，不自动当成新答案信息。关于不同年份的相似段落也不能因“相似”就误去重。

## 5. G1：先建立可用的结构骨架

### 5.1 阅读顺序与反向遍历

代码检查发现 `EvidenceNet/scripts/vldocir_reading_backbone.py` 已能导入经审计的NEXT并生成PREVIOUS，验证端点、文章归属和环；但明确保留限制：当前single-document profile只导出page-local flows，不合成跨页或singleton连接。

下一实现者必须检查实际上游输出，不能以“已有importer”推断已经有完整跨页阅读链，更不能直接设置ready=true绕过失败。

工作项：

1. 记录Dolphin/block/member到最终node的顺序映射，保留多栏、浮动图表、过滤节点的处理依据。
2. 先导入真正有效的页内NEXT，并确保反向访问存在。
3. 根据文章归属及已验证的跨页连续性补跨页NEXT；不跨未知页、不同文章或错误列序盲连。
4. 构建同文档page/section到子node的包含索引，作为导航路由结构；它不传递答案支持，不把整页node做成全连接。
5. 保存孤立节点及原因，逐一检查之前8题Top10的前驱/后继和包含层可达性。

### 5.2 NEXT是基础，不是任意远距检索的保证

一个末尾node能PREVIOUS回退，不代表2跳就能到达隔数页的证据。必须记录实际node跳距，不用页码差替代。

对远距信息，使用章节/页面层级路由或来源明确的引用连接，避免靠反复NEXT遍历整篇文章。层级路线选择同样受到query、访问量与tokens预算约束。

验收：有效结构范围内没有无理由断链、跨文章误连、自环；反向遍历可用；覆盖数与未知数完整报告。图可达不等于证据充分。

## 6. G2：补“证据单元归属”，解决页命中但段落丢失

优先构建以下可由原文、版面和明确引用核验的联系：

- 图 ↔ 正确图注 ↔ 显式讨论该图的正文；
- 表 ↔ 标题/表注/表头 ↔ 引用该表的说明；
- 公式 ↔ 变量定义、成立条件、推导或应用段落；
- 段落 ↔ 必要标题/小节/指代来源。

具体要求：

- 图表编号、公式编号作用域限定在正确文章；两个论文的Figure 1不是同一对象。
- 距离近是候选依据，不是归属证据；多栏与跨页图注需要单独检查。
- 公式相同字母不代表语义相同；变量改名也可能等价。保留变量角色、单位、条件与用途，不按外形同一性强判关系。
- caption不能替代视觉中才存在的信息。任务需要图像时记录图像来源与实际可见性；不要让纯文本核验器补想象。
- 把完整支持依赖作为可展开的原文组，而不是把长上下文永久拼入每个node embedding。

同时新增定位对照：H1当前每页1个node，另测固定预算下每页少量候选或由结构邻居补上下文。所有组用相同定位/压缩能力，并记录页内增加的曝光，避免把“多读几个node”全部算成edge语义效果。

验收：从正确页面上的入口node能访问该页内必要表头、图注或解释；若来源不存在或不可判，保留unknown而不生成假联系。用移除必要上下文的负例检查支持是否正确降级。

## 7. G3：改造语义候选发现与核验

### 7.1 召回多路候选，避免全局预算只覆盖少量热点node

复用现有node/view向量、词法与标识符索引，增加来源明确的对象及条件线索。每个eligible node获得候选提名机会，分别记录：

```text
eligible → 各路候选 → 文章路由 → 预算保留
         → 核验准备 → 核验通过/拒绝/未知 → 导出 → 实际导入
```

现有 `run_evidence_edge_pipeline.py` 和 `repair_edge_candidate_allocation.py` 已有文章路由、escape及reference预算。先检查实际配置和每阶段丢失，不直接无上限增大总pair数。

建议候选通道：原语义近邻、精确实体/对象编号、同对象不同条件、明确引用/指代、结构归属。对跨文档候选保留独立配额和escape；结构边不占用同一套昂贵语义核验配额。

预算以去重pair计数；按node覆盖、文档和候选来源分配，避免少数高频实体抢完预算。具体top-k和核验预算在pilot前冻结，作为可调配置，不给未经测量的“最优”数值。

### 7.2 核验必须说明两端分别带来什么

保留开放关系句和原文锚点，增加可核查的两端角色：

```text
shared_object / identity_basis
source_contribution / target_contribution
differences_in_time_condition_property
relation_statement + limitations
source_spans / target_spans
description_profile / input_hash / verifier_status
```

这些字段不能用模型先验替代出处；生成文字是检索线索，不是原始证据。无足够依据则拒绝或待审。

两端用途应支持分别呈现A→B与B→A的导航视角。例如A提供对象身份、B给出数值；反向访问的价值是补身份，不应仍称“去找数值”。与当前query是否相关仍在线判断。

反例必须包含：同词不同实体、同实体错年份、同材料不同物理量、同一基础公式不同条件、重复背景、表格缺身份、不同论文相同图号。不能只用随机负例估计错连率。

### 7.3 不对任意比较对象强建永久边

NGC3256与SN H0pe、两项不同研究资格比较等，可能只有query把它们放在一起。适合按query子需求建立多个检索入口，再在各自来源中局部导航。

可试entity节点，但实体消歧、单位/年份作用域与高频hub必须可控；同一个宽泛词不应变成整库跳板。它作为单独图版本消融，不作为本轮默认的大改动。

## 8. 在上线前测图本身的可用性

把“边真实”和“边能帮助搜索”分开评价。

离线图报告至少包含：

- 每层端点覆盖、孤立原因、候选漏斗、边数、度数分布和热点；
- 来源归属正确率、hard-negative误连、不同条件/实体混淆；
- 原文锚点与source hash完整性、生成描述超出来源的比例；
- 从固定seed在固定跳数/预算内可达的来源范围；
- 重复信息与互补信息的分布、各层贡献。

query/gold可作为独立诊断评估可达上界，但不得参与这些冻结图的生成。既有24题用于回归，新标注需覆盖未参与调试的文档/对象，并隔离训练与评估。

不能以“edge更多”“所有node都有语义边”“LLM格式通过”验收。结构有效性可以要求严格；语义精度与收益阈值应在看新结果前约定，并与旧图作对照。

## 9. 查询接口的最低修复，防止新图再次没有被正确使用

建图是本计划重点，但以下接口若不修，换图仍难解释：

1. 显式区分known source与new target；direct gain必须来自目标的新内容或它补充的必要联合条件，不能引用入口事实充数。
2. 对结构边给予有限的信息获取预算，不能要求未读目标先已完整回答；读后再决定是否进入最终输入。
3. 观察说明与真正missing分开，禁止把任意observations复制成缺口。
4. 保留可兼容的edge embedding索引；query编码可以在线，node/edge不按query重建。固定图下分别测描述可见性和向量排序，不把它们混称一个已完成机制。
5. 停止条件依据核实的来源充分性；已充分的样本可以停止，未充分却无路需报告图限制。
6. 同一目标通过不同路径到达时复用读取但保留路径出处；联合证据与短单段公平竞争预算。

## 10. 下一轮具体执行顺序

### 阶段A：只读诊断与输入修正

交付24题逐阶段漏斗：gold页是否进候选、该页哪些node被定位、必要原文是否存在、是否被评估/保留、为什么丢失。使用独立evaluator，不向选择器暴露gold。

复核H1每页1-node限制，明确整页/多node文本及视觉证据缺失；保持原H1结果不变，新定位器另名。

### 阶段B：结构图与归属图

固定旧语义图，先验证NEXT/PREVIOUS实际被导入，再加包含和归属连接。用先前语义孤立题检查覆盖变化，不强求每题提高。

### 阶段C：新语义候选与核验

固定结构骨架，比较原候选策略与覆盖/互补候选策略。保留每阶段拒绝原因，抽查hard pairs；先验证边质量，再扩大生成规模。

### 阶段D：共同检索入口上的图消融

至少保留以下组，按阶段逐步运行，不一次替换所有模块：

| 组 | 入口 | 图 | 目的 |
|---|---|---|---|
| H0 | ColNomic原始页排名 | 无 | 外部原生页级对照 |
| H1 | ColNomic页候选→冻结定位器 | 无 | 同选择器外部对照 |
| N | 原node similarity | 无 | 内部无图对照 |
| N+R | 与N相同 | 阅读/结构层 | 结构增量 |
| N+R+A | 与N相同 | 结构+证据归属 | 定位与上下文增量 |
| N+R+A+S | 与N相同 | 再加新语义层 | 互补语义增量 |
| H1+Graph（后续） | 与H1相同 | 同一图 | 检验图是否也能帮助强外部检索器 |

旧187条语义图保留为对照版本。若定位器由每页1node改为多node，H1与图组应同时有同能力对照；query split也另作消融。

页级指标使用冻结聚合/重排协议；最终原文按同一支持、压缩与预算协议比较。图组的额外候选要与额外dense扩展作预算对照，同时记录实际模型tokens，不将相同node数视作完全等价成本。

## 11. 如何判断这次建边调整成功

需要完整的证据链：

```text
原始seed → 真实离线边 → 新访问原文
        → 相对已有集合新增支持/约束
        → 最终保留必要片段
        → 同预算下质量提高或同等充分性下成本降低
```

每个宣称救回的案例报告原始排名、路径层、目标前后位置、引用来源和对照组是否已可取得该证据。完整报告退化与无收益题，不能只展示成功路径。

目标不是强迫edge每题都被用到。允许它在初始检索已充分时不工作，但在需要补上下文或遗漏内容时应有可用路线和可测贡献。

如果新图仍无收益，按漏斗定位：图无可达内容、边语义不对、目标已冗余、预算/排序丢失、支持/压缩误判。不要再把所有失败一概归因于关系类型不够多。
