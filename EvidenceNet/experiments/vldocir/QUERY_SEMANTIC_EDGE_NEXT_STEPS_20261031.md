日期：2026-10-31。用途：指导下一模型实施代码修改、设计实验并解释结果。

**本文是改进建议与验收要求，不是已完成实现。** 本次只审查代码、复现一个局部表达式错误并编写文档，没有修改 pipeline、改变冻结结果或提交 GPU 任务。

## 3. P0：先补真正走边时的正确性

### 3.1 已确认的潜在 TypeError

文件：`EvidenceNet/scripts/query_semantic_edge_policy.py::pack_with_joint()`；冻结 r4 部署中也存在同样表达式：

```python
sufficient = sum(
    r["status"] == "sufficient" and r["support_facts"]
    for r in assessments[pid]["requirements"]
)
```

当某项为 sufficient 且 support_facts 非空时，`and` 返回列表，`sum` 会进行整数与列表相加，触发 TypeError。局部表达式已在CPU上复现。最新真实 smoke 没进入联合选择分支，因此并未遇到这个错误。

建议修为明确的布尔计数，例如 `sum(1 for r in ... if ...)`，并补实际混合场景测试。仅修改这一行还不解决联合选择策略的冗余问题。

现有测试涵盖联合组两端原子入选，但没有充分覆盖“联合组之外还有充分支持的普通段落”。至少新增：

- A+B联合支持，同时C有独立充分支持；不能报错，也不能遗漏C补充的另一需求。
- A+B因预算放不下，C单独可以有效支持；应正常回退。
- 多个联合组共享节点；不重复添加原文，不丢失不同来源路径。
- 普通段落已经充分，联合组只重复它；不能因为“有边”优先占用预算。

### 3.2 实验必须报告实际执行了什么

每题/每arm输出以下统计，不能只写 `complete=true`：

```text
seed_assessment_complete
seed_sufficient / unresolved / unknown
frontier_count、eligible_route_count
navigation_call_count、description_visible_route_count
followed_route_count、visited_new_node_count
joint_audit_count、valid_joint_group_count
stop_reason、exception、validation_issues
```

没有导航时明确标为 `not_exercised`，而不是“描述无效”；有未解决校验问题时保持unknown，不把它当作已经没有信息或已经完整回答。

### 3.3 隔离版本与缓存

当前新runner复用了 adaptive v2 的执行模块，并通过 policy 切换运行。下一版应把可变策略依赖传递清楚，或提取稳定公共执行模块，避免对共享旧模块的修改悄悄影响历史方法重跑。

冻结实际部署代码与hash。缓存身份至少包含完整输入、model/revision、解码配置、prompt/schema/policy版本；同一个调用在两个arm输入完全相同时可以复用，但成本要同时报告冷运行逻辑成本与实际缓存后成本。

## 4. P1-A：先判断每题是否有需要、是否有路

### 4.1 为什么 Federer 不能独自承担导航测试

Federer 的两段正确原文已经在Top10中，选择修复后立即停止是合理行为。强迫它走边并不自动提高质量。需要把“来源选择回归”与“导航能力验证”分开。

先对24题冻结初始query-only需求、Top10和初始来源审查。已有相同输入缓存可复用；没有缓存的模型判断必须实际运行，不把静态分析伪装成测得的充分性。

对每题记录：

| 类别 | 观察 | 优先检查 |
|---|---|---|
| A | Seed已足够，且没有明显来源问题 | 合理停止；可单列低成本精简探索 |
| B | Seed尚缺证据，存在可访问邻居 | 导航最值得测的情形 |
| C | Seed尚缺证据，但允许跳数/范围内没有新节点 | 图覆盖或入口问题，query-edge排序无从发挥 |
| D | 访问到相关来源，但未形成最终充分证据 | 支持归属、联合选择、压缩问题 |
| E | 模型判定充分，但原文审查发现缺约束 | 充分性误判与过早停止 |
| F | 校验未知或预算中断 | 工程状态，不能混进确定的质量错误 |

这些类别来自不同阶段，可记录多个标签；不是预先根据gold挑有利题目。

### 4.2 图可达上界必须与在线选择分开

离线计算Top10的一/两跳可达集合；独立evaluator再对照来源页gold或单独标注的证据。

- 区分“gold页可达”与“真正需要的段落可达”；同页不保证同证据。
- 不可达时说明缺在seed入口、缺边还是跳数预算。
- gold只能用于评估与事后诊断，不能输入路线排序器、补边器或支持判定器。
- 在线选择依然只用query、已见原文和离线图。
- 报告完整24题分母，再分层分析；仅报告B类的成功率会高估整体效果。

### 4.3 机制测试与真实质量测试分开

构造受控小图测试rank10入口、两跳bridge、错误年份、同实体错属性、循环和多路径；它们证明代码机制，不计入真实 Recall/AP。

若需要强制一跳来验证模型调用，可另开明确命名的诊断arm。不得修改正式Top10、删除正确seed或按gold补边，制造“原来没有找到、靠edge找到了”的结果。

验收：生成一张完整逐题表，解释每题为什么走或不走；导航分支若没有真实触发，报告不可判断效果，而非继续换一个已经充分的单题smoke。

## 5. P1-B：把新增来源改为新增支持

### 5.1 当前问题的机制

`fact_key()` 以 `(requirement, packet_id, span_ids)` 标识支持。它能保证来源可追踪，却不能判断两个来源是否说了同一件事。`actual_gain()` 也主要比较状态与引用签名，引用换了并不一定表示语义收益增加。

尤其要把“支持增加”“来源替换”“支持退化/发现矛盾”分开：现有 `new_or_changed_support` 中也可能包含 sufficient 降为 partial，不能把所有变化都统计成正收益。

Federer 的P019赛事表与P000重复提供2004年的三项大满贯信息。现选择器仍把它当gain，于大预算时加入整表。

**不要简单删除 packet_id 或给 meaning 文本做hash就当语义去重。** 同一句话可能来自不同实体/年份；同一事实也可能用不同措辞表达。保留来源身份，单独判断支持增量。

### 5.2 建议用已选集合条件下的边际判断

针对当前选中原文集合S与候选P，判断加入P后：

- 是否补上此前缺失的事实、实体身份、年份、单位或范围？
- 是否补全枚举，或使原本partial的联合支持充分？
- 是否揭示矛盾，需要进一步核查？
- 是否只是重复已充分的支持？
- 是否提供独立佐证？若query/任务没有要求重复佐证，应明确其优先级与预算，不自动当新增答案信息。

建议输出为可追踪的决策，不强制模型重抄数值：`requirement_id`、`before_status`、`after_status`、`gain_kind`、必要span IDs、保留/跳过理由。它们是选择器状态，不是限制edge种类的关系taxonomy。

首先用廉价的原文/身份/约束比较排除明显重复，只对有歧义的候选调用集合审查；不要给每个候选都无上限增加多次LLM判断。

### 5.3 选后做有预算的删除检查

从选中集合逐个或按必要来源组尝试删除：若剩余原文仍保留同等必要支持、约束和冲突信息，则移除该冗余内容。记录删除前后支持与成本。

不能删除唯一的身份来源、表头、枚举完整性依据或必要否定。若判断unknown，保留来源或记录不确定性，不为追求短文本强行删除。

验收：

- Federer在大预算下不再无理由加入整张重复赛事表；不把“必须恰好435 tokens”写成硬编码目标。
- A2063G总体趋势不能替代两个年份的具体数值；Graf的部分奖牌不能覆盖完整集合。
- 同实体同属性但不同年份的事实仍被保留；同义改写不被无条件重复收录。
- 更大预算可以保留更多必要证据，但无需把预算填满。
- 以独立原文核查确认充分性，不只依赖同一个选择模型给自己的高分。

## 6. P2-A：让 Query 真正利用关系语义

### 6.1 先验证描述，再加向量排序

当前endpoint/semantic仅在生成描述是否可见上不同。建议先让真实缺口题进入该分支，回答：同一图、同一来源锚点下，描述是否改变访问决策？改变后是否得到新证据？

已有描述是legacy版本。未来一句话约束应作为单独版本，保留主体/差异/作用及关键限定，不能仅为短而删除否定或年份条件。协议有效不是语义正确；优先审查实际被query使用的边，同时抽查未被使用/被拒绝的边，避免只看成功路径。

### 6.2 再接入离线 Edge embedding

不重复编码整个语料。复用旧 `run_vldocir_edge_embedding.py` 的数据校验与编码流程，核实模型和实际输入hash后才能复用向量。

推荐处理链：

```text
query / 未满足需求的向量
  → 对所有seed提出的现有路线做edge语义粗排
  → 在固定预算内看source上下文、关系及target锚点
  → 判断预期补充的证据或bridge依据
  → 访问原文并验证实际收益
```

- Query与edge向量使用兼容encoder及预处理。历史0.6B query表示不能直接与8B edge表示点乘。
- 端点相似度、关系匹配、来源可靠性和信息增量分别保存；相似度不直接作为事实置信度或最终排名bonus。
- 排序单位是 `(source, edge, target)`。从A去B与从B去A的用途可不同，导航方向不自动表示因果。
- 全部Top10都有提出路线的资格。预算可以限制最终访问量，不能在入口处只保留已经选中或排名第一的seed。
- 允许bridge暂时不覆盖答案，但要求来自真实边与锚点的后续线索，限制深度和总预算。
- 当前图很小，向量排序可能不会改变访问集合；仍要记录排位和截断，不能把“已接入向量”当成效果提升。

验收：保存实际编码文本、模型/配置hash、每条路线的匹配分数、description使用情况、预期收益与读取后的实际收益。相同图下对比endpoint与relation表示；新图和新encoder另做实验。

## 7. P2-B：联合证据要有竞争，也要影响正确的位置

### 7.1 避免联合组无条件优先

当前 `pack_with_joint()` 先放联合组，再放普通packet；不同组还主要按来源签名去重。即使修复TypeError，也可能让冗长的组压过一个已能独立充分支持的短段落。

建议把单段与联合组统一视作候选来源集合，在同一预算下比较边际支持和新增原文成本。共享片段只计算一次追加成本；重复组不算新的语义事实。

联合组必须来自实际原文支持，不能因为两端有edge就成立。没有edge的来源也能共同回答问题，无边baseline应具有同等基本多来源核验能力。

### 7.2 区分条件、归属与答案事实

P019的孤立表格没有直接写Federer姓名，但模型称它显式列出Federer战绩。今后需区分：

- 数据单元格提供什么事实；
- 哪段标题/表注/正文建立主体、年份与单位；
- 是否存在明确、可追踪的归属关系。

同实体词出现、同页、文档标题或edge生成描述，都不能无来源地变成事实证据。确需上下文时携带最短的原始上下文并计入输入成本。

### 7.3 处理导航状态与联合支持的接口

当前轮后充分性审查主要依据普通pack，单独的joint arm在最后形成。联合证据可能已经足够，却没有进入下一跳停止判断。

先做固定访问集合的联合核验消融，测选择效果；若要把联合核验反馈给后续导航，另设策略版本，记录它如何改变停止与访问量。不要同时变访问集合又声称只测联合排序。

验收：存在一个可控案例，两段单看均不充分、联合后充分；删除必要身份来源后判定应降级。另有一个案例，短单段已充分，冗长联合组不能仅因有edge胜出。真实案例仍独立审查。

## 8. P3：精准输入、成本与图覆盖

### 8.1 精准到片段与表格单元

先选对whole packets，再把相同压缩器应用于所有组。输出原文span及位置，不用生成的关系或摘要替换证据。

表格保留必要表头、单位、行标和数据；非连续片段标明分隔；正文保留否定、指代、年份和对象。压缩后再次核验必要约束，缺失则补回或报告不足。

当前只包含文字packet的实验不能代表图片/公式的视觉语义已验证。多模态来源后续要记录caption、视觉输入及上下文的实际可见范围。

### 8.2 成本同时看两层

分别报告最终证据tokens和在线全部模型成本。可复用完全相同的query plan/独立packet评估缓存；减少不必要修复调用及重复集合审查。分组收益不能建立在一组多看了候选或多用了模型却不计成本上。

在质量不退化的条件下减少最终输入，同时展示前处理多花了多少成本。不能将435 tokens与15358输入tokens混成同一个指标。

### 8.3 图覆盖按诊断补，不按gold补

若大量题属于“缺证据且不可达”，再单独扩大离线候选来源：每node候选覆盖、实体/标识符、词法与向量召回、跨文档路由预算等。核验通过才建边，不保证每个node一定有边。

NEXT/PREVIOUS、reference、same-entity/entity-node路线分别标记来源并单独消融。当前冻结图未导入ready阅读顺序层，不能直接把待处理NEXT当成正确结构图。

高频通用实体、基础公式、宽泛同主题关系容易扩散到无关区域；记录节点度数、hub暴露与错连率，限制访问预算。结构或实体连接表示可导航联系，不自动表示答案支持。

公平比较：无边dense扩展作为基础对照；拒绝的目标锚点也计信息暴露；同时报告节点数和tokens成本。相同节点数不代表完全相同信息量。

## 10. 指标、日志与停止规则

至少分别报告：

1. **工程完整性：** 计划样本数、完成数、失败/unknown、实际执行分支。
2. **可达性：** seed/一跳/两跳来源范围、缺边与预算截断。
3. **导航：** 实际新增节点、错误路线、描述使用比例、经边新增的核实证据。
4. **最终选择：** 必要事实/约束保留、充分题数、冲突与遗漏、重复原文。
5. **排名：** 统一页级聚合和tie-break后再算Recall/AP/nDCG；未生成排名则不报告AP。
6. **成本：** 最终tokens、上游输入输出、调用、冷/缓存成本及耗时。

Query已经充分时合理停止；可另设小预算的“找更短替代证据”实验。不要以每题都走边、每题都填满预算、每题都产生edge收益作为成功标准。
