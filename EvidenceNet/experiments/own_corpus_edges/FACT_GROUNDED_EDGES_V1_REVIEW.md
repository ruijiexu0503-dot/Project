## 失败原因与下一轮修改建议

105 个节点中 80 个 READY，25 个 FACT_PENDING。抽取失败中 17 个是主体字面
匹配失败，另有超出事实上限、主体类别、视觉观察或证据 ID 等错误。
例如原文 `Open Sci-\nence Policy` 与模型正常拼写 `Open Science Policy` 无法匹配；
`U-platform infrastructure` 可能是跨句身份归纳，不能按单一连续字符串检查。
当前单条不合格事实会使整个节点失败；不应把所有这些失败都归为模型幻觉。

1. 分开原文 mention 与规范实体名，保存原文位置及规范化映射；逐事实隔离错误，
   保留其余支持充分的事实，同时记录不完整覆盖。
2. 添加公式和表格的符号／数值事实表示，保留变量、条件、单位与参考系。
   空事实应表明表示不足，不能证明没有关系。
3. SAME_PROJECT / SAME_EVENT 应检查参与者、项目／事件角色与条件中的身份，
   不能要求两条断言的语法主体恰好都是 PROJECT / EVENT。
4. 明确证据 ID 的数组协议并逐项验证本端归属；分开多锚点格式失败与真实串端。
   直接组 20 个格式失败中 17 个涉及 anchor_not_in_endpoint，需先修复协议。
5. 同对象关系要求身份依据；外观或任务相似不足以证明同一对象。定义与方法边
   必须包含具体定义／机制，不能把相关工作主题列表提升为定义。
6. 复跑同一固定样本后，再同时检查接受与拒绝侧，并为重复节点对去重。
   修复后仍需检索实验才能决定是否接入 pipeline。
