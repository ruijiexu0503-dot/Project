## 保持可比性与来源记录

- Embedding 仍用 Qwen3-Embedding-0.6B，左侧 padding、512 token 截断、最后 token pooling、L2 归一化、8 条 batch 和同一候选预算。CPU 使用 float32；原 GPU 用 BF16，因此候选排名不保证逐位相同。不得当作纯设备无差异复现。
- 语义验证仍用 Qwen3.5-35B-A3B、BF16、相同提示、1800 token 上限、相同两次格式尝试及原图锚点校验。没有替换成小模型，也没有修改上次发现的语义问题。
- 强制 CPU 放置，清空 CUDA_VISIBLE_DEVICES，检查实际参数设备。`cpu_execution_manifest.json` 记录输入、适配代码和模型客户端 hash、设备、精度；每对响应记录实际耗时和线程数。候选文件生成后冻结 hash。
- 小样本保存到同一候选的 decisions 断点，可供全量复用；不会写出代表完整实验的 semantic_edges.jsonl。

## 耗时门槛与结果解释

两对响应都通过格式／锚点检查后，以较慢的一对耗时 × 全候选数量 × 1.5，加模型加载时间，估计全量耗时。该估计仅是保守执行门槛，两个样本无法保证覆盖所有长度／视觉成本。
预计不超过 40 小时时，75115 自动继续；超过则不加载大模型，保存 `cpu_full_status.json` 的 DEFERRED_RUNTIME_ESTIMATE 状态。48 小时是资源上限，不是预计完成时间。
实测失败会阻止全量依赖启动；75117 仍生成部分报告。实际完成的 decisions 可以续跑。

验收包含 7 项通过的相关测试：小样本不发布完整图、后续复用断点补齐剩余候选、超时估计在加载前暂缓、拒绝意外 GPU 放置，以及原语义候选与锚点规则检查。CPU 实际模型速度和兼容性以 75114 为准。

上次小型诊断已经发现两端技术细节混淆和窗口条件遗漏。CPU 迁移不解决这些语义问题，所有接受边仍需来源复核；尚未验证检索收益。
