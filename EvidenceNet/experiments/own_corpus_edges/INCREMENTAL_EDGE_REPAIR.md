# 逐项修复与文章候选路由

日期：2026-10-12。基于独立事实 v1 的冻结输出开展开发回归。

## 每次仅改变一项

每项实验保存失败原因、来源节点、原始响应、旧结果、新结果、代码版本和
剩余失败原因。对应错例必须同时配已通过的样例和负例；不能只检查修复目标。
把解析／来源匹配通过、事实支持检查通过、关系判断正确、检索收益分开记录。
开发错例可用于修复，但不能用作最终无偏准确率；扩大运行前需另外冻结未参与
修复的样本，并检查接受和拒绝两侧。测试预期以原文／原图复核为准。

## 文章优先作为另一个独立实验

建议实验顺序：先使来源与输出协议可用，再加入文章级候选路由；不在同轮
同时改事实表示与候选算法，否则无法判断改善来自哪一步。

1. 保留现有文章分割与跨页归属，标记未知归属；论文通常是一个文档一篇文章，
   杂志需有可靠边界，不能把整本杂志作为一篇文章。跨页未确定时不强行合并。
2. 从属于文章的 evidence node 汇总标题、关键实体／事件／项目、方法和带
   限定的发现，保留每条信息的来源 node ID。原图仍保留在 node；图像描述可
   帮助候选召回，但不能代替原图成为关系证据。
3. 文章摘要 embedding、实体／项目索引、明确引用共同提出文章对候选。
   文章相似或引用只能证明候选有价值，不能证明其任意段落相连。
4. 在候选文章对内，按查询 node 的文本、视觉和实体／方法特征检索另一篇的
   top-k evidence node，再核验具体类型、方向和原文／原图锚点。
5. 并行保留全局 evidence-node 直接候选路由，为摘要漏掉的少数细节和文章
   归属未确定的节点提供入口；文章内邻接、图注／几何、公式介绍单独保留。
6. 最终文章级证据边由通过核验的 node 边聚合，保留 supporting_edge_ids。
   文章级候选和已经成立的文章证据边分别存储。

这样仍以多模态 evidence node 为最小单位，不需要把图片变成纯文本节点，
也不需要将一个混合 node 拆成纯段落端点。文章关系用于缩小搜索范围、补充
上下文；阅读顺序不由文章语义相似推断。

试验对比固定相同 node 输入、关系核验器和总核验预算：现有 node 路由与
文章加 node 双路由。检查已知有效跨文章 node 对是否被召回、漏掉哪些细节、
重复候选与核验成本、最终边的来源正确性。待这些稳定后再测检索质量；不能
单凭文章对更少或边更多判定效果改善。
