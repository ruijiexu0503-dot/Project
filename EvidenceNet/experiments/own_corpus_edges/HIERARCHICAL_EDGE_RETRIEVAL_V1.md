# 分层文章路由与 evidence edge 召回 V1

日期：2026-10-14。输出：`EvidenceNet/output/hierarchical_edge_retrieval_v1_20261014`。

目标是将文章搜索范围与 evidence node 语义关系拆开，并测量在不调用生成模型的情况下，是否能以较少候选找回已核对的方法关系。
本实验复用交通／土地覆盖语料已完成的 160 页、763 个 evidence node，不修改正在运行的 432 对 CPU 基线。

## 数据对象

- Evidence node：唯一的最终语义边端点，保持原样。
- Retrieval view：节点内部用于检索的原文窗口、带表头的完整表格行、视觉描述窗口。它不是图节点，也不能独立发布为 evidence。
- Article routing candidate：只表示值得在两篇文章之间继续搜索，不是文章语义边。
- Node candidate：等待具体关系核验的 evidence node 对。
- Article semantic edge：只能由来源审查通过的跨文章 node edge 聚合，并保存支撑 node-pair IDs。本轮召回阶段不会生成它。

当前六份材料都是单篇论文，一份 PDF 对应一个 article ID。这里验证分层路由和节点召回；杂志的一份 PDF 多文章、跨页归属需要在独立文章分割输出上运行同一接口。

## 不使用生成模型的召回

1. 每个合格成员切成 96 token 窗口、72 token 步长，减少长节点被一个平均向量稀释。
2. HTML 表格增加“表头 + 完整行”视图，同时保存原始 `<tr>` 锚点，避免数字窗口脱离字段和单位。
3. 使用 Qwen3-Embedding-0.6B CPU float32 编码 1544 个视图；这是 embedding 模型，不调用 Qwen 生成模型。
4. 结合视图级 dense、BM25 和明确标识符倒排。长节点的多个视图只取每个方向和通道的最佳贡献，避免文本越长票数越多。
5. 每篇文章选择两个文章邻居；每个入选文章对最多保留 16 个节点对。
6. 额外保留最多 96 个跨文章全局候选，避免文章路由变成新的硬门槛；每篇文章内部最多 8 个候选。
7. 所有候选均带触发通道、最佳视图和原始节点 ID，后续轻量重排或 Qwen 核验可以直接追溯。

这些预算是第一版诊断设置，没有用六对参考标签调参。参考标签只在候选文件完成后用于报告覆盖率。

## 验收问题

- 三个已核对方法正例能覆盖多少？旧全文单向量方案只覆盖 DCRNN 1/3。
- 三个难负例中有多少进入候选？进入候选不是误连，只代表后续验证成本。
- 候选总数相对旧方案 432 是否下降？
- 正例由文章路由找到，还是依赖全局逃逸通道？后者可以揭示文章层漏召回。
- 表格与数据集候选是否保存完整行和表头，而不是只有局部数字窗口？

通过召回门槛后才接关系验证器。下一版验证器应先冻结两端各自有原文锚点的声明，再比较共同机制、差异和条件；数据集身份要求明确名称或来源标识，视觉类别相似不能建立同一数据集关系。
