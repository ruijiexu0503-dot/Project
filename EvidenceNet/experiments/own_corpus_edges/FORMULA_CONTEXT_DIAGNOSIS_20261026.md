### F015：需要解释 Key，却只取到相邻 Q/V 公式和残缺引入句

Task：`REL_e29da5720b66c216`。

- A：`traffic_st_transformer_2001_02908_5_HY_008`，原式为 `K^S = Xhat^S W_k^S`。
- B：`traffic_htvgnn_2401_10155_4_HY_002`，原式是一组 `Q_i = X W_i^q`、`K_i = X W_i^k`、`V_i = X W_i^v`，并说明权重是第 i 个 self-attention head 的可学习参数。
- A 加入的两段 context 是相邻的 Q 公式和 V 公式，route 为 `previous_reading_node`、`next_reading_node`。它们没有解释当前 K 的语义。
- B 加入的 context 是：`$V_i ∈ R^{T×N×d_v}$ are generated by the linear projection as defined in Eq.(1), respectively.`。这是一个以 V 开头、以 respectively 结尾的片段，没有完整呈现 Q/K/V 的前置定义。这里说的是**新增 context 片段**，不是说 B 端点本身没有解释；B 原始 input 和原图均已有关于可学习权重的 where 段。

control 已经识别到两个端点都计算 Key matrix，但只给 N。context 组强调“different inputs, superscripts, and variable sets”，因缺少 explicit comparison/shared subject identification 而给 X。它将模型实例是否相同的标准套到了局部操作对应上。

需要验证的修复是：恢复有来源的完整定义，把 `K^S ↔ K_i`、`Xhat^S ↔ X`、`W_k^S ↔ W_i^k` 作为**本次局部角色对应**，保留张量、空间/时间及 head 差异；不能因此声称参数、数据或模型实例相同。只比较 `K=输入×可学习权重` 也不够，仍需原文/原图支持这里确为 attention Key projection，避免把任何线性层都错连。

### F033：两端都是指标，不代表定义了同一个指标

Task：`REL_2398184e4b52316f`。

A 为 MAPE，B 为 RMSE。control 理由已经承认公式不同，却因“same purpose / domain”给 E。context 组继续以“same class of metrics”给 E。因此这是原有判定标准过宽，不能归为 context 新增错误。

context 的选取还会放大这种干扰：MAPE 端加入了相邻 **MAE** 公式，另有跨到下一页的 695 字符 where 段。后一段虽开头解释 y、预测值与 M，却继续谈 RMSE/MAE、Table 11、60 分钟预测期、DCRNN/STGCN/Graph WaveNet。真实来源只能证明摘录没有捏造，不能证明这些内容都适合解释当前 MAPE 公式。

应把“变量定义”与“其他指标/实验结果讨论”分开，仅使用有对应关系的定义作为 context。判定时分别列出运算与输出：绝对相对误差的平均 vs 平方误差平均再开根。共同领域或共同变量不足以建立定义对应。若用户未来需要“可替代评估指标”导航，应单独定义用途并重新标注，不能用这个理由覆盖当前 X 标注。

### F013：把跨文档的 “defined as follows” 当成了直接指针

Task：`REL_3806fc9bbe9b43dd`。

A 的原文是 `Some commonly used evaluation metrics, namely, RMSE, MAE and MAPE, are defined as follows:`，来自 survey；B 是另一篇 HTVGNN 论文的 RMSE 公式及变量定义。模型理由说 A 的 “defined as follows” 被 B 直接满足，因此给 DIRECT_COMPLEMENT。

这个局部指针实际指向 A 自己文档后续内容，不能凭另一篇论文存在一个 RMSE 公式就解释为直接指代。按照目前临时标注，共享具名指标只给 N。两组没有额外 context 且复用了同一预测，故不是 context 退化案例。

### F016：局部对应成立也不能宣称完整公式等价

Task：`REL_1a4b308c53ddbbb7`。

A 原式为 `S^S = softmax(Q^S (K^S)^T / sqrt(d_A^S))`，是 attention 权重/空间依赖矩阵。B 的提取原文为 `head_i = Softmax(Q_i K_i / sqrt(d_head)) V_i`，并包含后续多头拼接与输出投影。

两组均给 E，符合当前“局部机制对应”的临时标签，但理由使用 “identical structure”“core mathematical claim ... identical” 需要收窄：A 是权重子式，B 还乘了 V，并构成更大计算流程。本次已由主审阅者检查两端原 crop，B 原图确实写作 `Q_i K_i`、没有显式 T，且右侧乘 V；这里不能归因于本 pipeline 的 OCR 漏掉转置。维度和作者约定仍需另行核对，不能悄悄补 T，更不能声称二者数值等价。这是**接受结果符合当前临时标签、但解释过强**的审计风险，应与误连数量分开记录。

## 3. 旧 P12 为什么不能直接作为新算法效果的证据

旧 P12（`REL_c0eb7fee76e9cb41`）比较 DETR box loss 内的 L1 项与 STTN 的独立 L1 loss。旧 bounded 组因 object detection/traffic forecasting、composite/standalone 的差异拒绝了局部数学对应。

同时，旧 [supplemental_prompt](../../scripts/run_edge_context_ablation.py) 写的是：

> If removing the endpoint evidence would remove the claimed relation, choose NO_LINK

这相当于把“关系依赖端点证据”当成拒绝条件，方向反了。2026-10-20 [routed runner](../../scripts/run_routed_edge_context.py) 对 control 和 treatment 同时修正这条规则，并明确不同应用不自动否定原文显示的共享数学操作。P12 此后两组均为 E。

因此，旧 P12 能说明“模型会用整体任务差异否定局部子式对应”，但不能用旧 anchor/bounded 差值证明当前上下文实现仍有同样幅度的退化。

## 4. 已定位的实现问题

1. `run_routed_edge_context.py` 的 `preferred or immediate_context(...)` 在找不到专业公式上下文时，退回普通邻居摘录。`run_edge_context_ablation.py` 的 `immediate_context()` 直接取每侧一个邻居的首个合格 atom，最多 800 字符，不要求其是当前公式的定义，也不排除其他公式。
2. 该 fallback 不沿用 `formula_retrieval_views.py` 的“同页唯一 NEXT + 引入/where 语言线索”条件。F033 实际拿到了跨页下一节点；F015 实际拿到了 Q/V 邻居公式。`grounded_context()` 会检查同文章和原文归属，但这不等于公式解释关系已被验证。
3. 现有 `text_scope`/`text_readable` 只作用于 `group == prose`。公式使用相同 multimodal_context 请求，因此这两组相同的公式结果不是独立重复试验。
4. 当前模型解释把 notation 差异当作不对应的理由，也把共同用途当作对应理由。这两个方向必须一起修；只放松“不同变量也可连”容易扩大 F033 一类错误。

## 5. 最小可归因实验

保持节点、pair、原图、模型、token 预算、采样设置、标签、输出校验器和 edge 导出规则不变，隔离两个因素：

- **上下文选择**：旧邻居拼接 vs 有 provenance 的公式说明包。说明包只保留完整定义句、符号/角色、维度/条件，以及经核验的公式组归属；不将邻居公式或实验结果自动当作本公式定义。找不到可靠解释时保持缺失，不生成猜测。
- **局部数学对齐**：旧共同判定规则 vs 先定位两端对应子式，再检查操作、变量角色、输出层级及差异的规则。共同用途不能代替数学对应；局部子式对应不能升级为完整模型/完整公式等价。所有新解释字段都要指回原式或原文，不能充当新证据。

本轮准备了 2×2 对照（无额外 context/说明包 × 旧规则/局部对齐），另加旧 context 选择作为第五组。这样可以分别比较筛选上下文、调整数学判断和两者同时改变的效果，并与历史邻居拼接作对照。若只做“旧 context → 说明包+新规则”，无法知道改善来自选择还是判断标准。无需先扩展固定 edge 种类；可以先把对应范围和差异记录成可审计字段。

旧 6 对与 fresh 8 对分别报告。最低报告项：严格 E/N/X、useful recall、负例 accepted FP、discovery-only 变化、无效/缺失、局部对应来源是否正确、完整公式等价是否被过度声称。F015 应观察是否恢复有来源的局部 Key projection 对应；F033 必须检查有无误连；F013/F016 检查关系范围与解释，而非只看接受率。

这些样本都已被观察并用于设计修复，后续只能称为开发集回归。Fresh 标注也是 assistant source review 的临时标签，不是独立专家 gold；节点不重叠但文档重叠，重复端点使样本相关。修复后还需要新节点/新文档的公式对，包含等价变换、子式对应、相同记号不同角色、相同结构不同量纲、相同用途不同运算、OCR 缺项等对照，才能判断泛化。

**当前没有证据证明新的说明包或局部对齐规则已提升模型效果。** 本文结论仅支持上述错误定位和下一步受控验证，不修改正在运行的 VL-DocIR pipeline 对照。

## 7. 不同字母、同构公式和基础公式高频复用

用户补充的需求：字母不同可能只是改名，也可能代表不同公式；相同基础公式会被许多文章使用。以下为后续设计约束，**尚未在 5213537 实现结构解析或符号等价证明**。现有 packet 只抽取定义句，数学策略只是 verifier 提示词。

### 分开记录结构、语义和用途

1. **结构对应**：保留原 LaTeX/原图，再建立可解析的算子结构及候选变量映射。保留重复变量、绑定作用域、运算次序、转置、上下标、归一化与输出范围。重命名不允许把不同变量合成一个：`x+x` 对应 `u+u`，不因此对应 `u+v`。字母不敏感的签名只召回候选，不单独决定建立语义边。
2. **语义对应**：从各自原文核对变量角色、标量/向量/矩阵类型、维度、单位、定义域、聚合对象和假设。未知时保留未知。相同运算模板不证明相同物理关系或相同数据；不同任务也不自动否定共享的局部运算。
3. **使用与关系范围**：描述共享的原式/子式、成立条件及差异。例如两种应用都使用 L1 项，可以保留这一联系，但不能把它写成两篇论文结果互为支持。数学对应、描述正确性与检索用途分开评估。

必要反例：

| 对照 | 应检查的边界 |
| --- | --- |
| `sum_i x_i` / `sum_j z_j` | 索引范围、绑定作用域和变量角色；不能推导数值输入相同 |
| `x+x` / `u+v` | 重复变量关系不能被归一化抹掉 |
| `ab` / `ba`，以及 `AB` / `BA` | 标量交换不能推广到一般矩阵乘法 |
| `sqrt(x^2)` / `x` | 实数下需额外 `x>=0`；无此条件不能直接等价 |
| `E=mc^2` / `y=ax^2` | 模板相似不等于同一物理/科学关系 |
| 平均绝对误差的不同字母写法 | 可对应同一计算定义；预测对象、单位、聚合轴、权重和归一化仍需保留 |
| DETR 的 L1 项 / 交通预测的 L1 loss | 局部操作可对应；整个 loss、任务及实验结论未必对应 |

解析失败/OCR 歧义归入未知，不自动修补成教科书公式。限定表达式可用符号化简作辅助；不能证明时不直接判不等价，数值抽样只能提供反例或支持线索，不能作为普遍等价证明。

### 高频基础公式的图表示

保留每次出现的原 node 和使用上下文，并建立共享公式候选索引，避免同一基础公式出现 N 次就产生 N(N-1)/2 条跨文边。结构候选分组与语义确认后的公式家族分开，不能先把所有同构公式合并成一个概念。这个索引可以先作为独立 artifact，不要求改变现有 node generation。

具体跨文边继续使用候选配额和 verifier。频率按不同文档统计，用来限制重复扩展和调整默认检索优先级，不硬删除，也不降低“关系确实成立”的置信度。应分别记录：

- relation confidence：这个局部对应是否有证据；
- specificity：这种对应是否过于普遍，区分能力有多大；
- query relevance：已有关系是否与当前 query 有关。

当 query 就是在找某个基础公式或其应用时，相关公式实例仍应被召回。检索结果按论文/使用场景去重或分散，不能让同一通用公式的重复实例占满预算。

### 与 edge embedding 的衔接

离线保存公式结构视图与使用语义视图；edge 描述保存具体对应范围、角色映射、假设、差异和原文锚点。可采用开放描述，例如“共享 L1 残差项；分别用于框回归与交通预测；不代表完整目标函数相同”，无需先扩充固定 edge 种类。结构分数和语义分数先分开保留，避免整段上下文再次覆盖公式信号。edge 表示预先编码，query 到来时匹配已有索引，不重做文档/edge embedding。

后续测试需同时包含同式换字母、同字母不同含义、同结构不同类型/条件、局部子式对应、高频公式重复扩展，并单独测误合并、漏召回和最终检索指标。当前14对已用于设计修复，只能开发回归，不能据此确认上述泛化能力。
